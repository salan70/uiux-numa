# Catalog

公開サイト「UI/UX NUMA」の実装。
責務は [visual showcase の ADR](../../docs/decisions/2026-09-20-catalog-visual-showcase.md)、表示層は [topic-first の ADR](../../docs/decisions/2026-09-20-catalog-topic-first.md)、配色は [24 役割の ADR](../../docs/decisions/2026-09-20-catalog-material-color-roles.md)、公開手順は [catalog-publishing.md](../../docs/catalog-publishing.md) にある。
`just catalog-install`、`just catalog-dev`、`just catalog-test`、`just catalog-build` で扱う。

## 画面の設計判断

Catalog の画面に閉じた判断はここに残す。
新しい判断は表の末尾に足し、却下した案と理由を書く。
2026-09-24 より前の行は個別の ADR から移した。原文は commit `5215a3c` の `docs/decisions/` にある。

| 日付       | 判断                                                                                                                 | 理由                                                                                                          | 却下した案                                                                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-09-19 | Catalog の掲載を token と部品の視覚サンプルだけに絞る（後に visual showcase で置き換え）                             | 文章ページと検索は正本の二重管理を招く                                                                        | 文章ページを残す案はドキュメントサイトの骨格が残る                                                                                                             |
| 2026-09-19 | 採用案を正とする公開デザインシステムサイトにする（後に visual showcase で置き換え）                                  | 採用案と比較資料を見分けられる                                                                                | Astro 移行は利用者が Vite + React 継続を選んだ                                                                                                                 |
| 2026-09-19 | ホストを見本帳の比喩で作り、余白 2 個だけ token に取り込む                                                           | 採用成果が主役になり、クロムは構造だけになる                                                                  | 公開面の 3 スキンを Experiment にすると比較軸がサイト全体になる。display token は用途が見出し 1 つ                                                             |
| 2026-09-19 | 部品一式を Experiment の 4 案で比べ、`hairline-float` を採用する                                                     | 部品の見本なら Catalog を残して比べられる                                                                     | Radix UI は依存が大きい。自作 headless は Select や Drawer の操作を再実装する                                                                                  |
| 2026-09-20 | 方針ページを足し、`docs/guidelines/*.md` を二次情報として載せる                                                      | 判断の背景を確かめられ、1 文書 1 主題で関心から引ける                                                         | 公開 Design System サイトに戻すと文書が主役になる。1 規則 1 ファイルは主題で束ねられない                                                                       |
| 2026-09-20 | 面を白黒基準にし、公開カテゴリから Illustrations と Motion を外す（Motion は後に戻す）                               | 無彩色の面は成果物と scheme 固有色の競合を減らす                                                              | scheme 色で背景を染め続けると成果物より先に見える                                                                                                              |
| 2026-09-21 | 方針画面の箱をやめ罫と濃淡で階層を出し、サイドバーを畳めるようにする                                                 | 箱は中身より先に読まれ、器が読む順を決めてしまう                                                              | 良い例と悪い例の折りたたみは操作が 1 回増える                                                                                                                  |
| 2026-09-21 | 規則を bad / good の対に組み直し、行長の上限と節の日本語見出しとフッターをやめる                                     | 対を軸にすると図版と文と例外の所属が位置で決まる                                                              | ラベルの桁を通す案は `bad` の重複が残る。索引をやめると全体像を追えない                                                                                        |
| 2026-09-21 | 規則を 4 段に固定し good と bad を左右の対にし、図版を廃止する                                                       | good と bad は唯一の対で、桁にすれば残りの段が対の外だと位置で決まる                                          | `labelled-column` は本文が右へ寄る。`heading-blocks` は縦が長い。`meta-aside` は狭い幅で縦に積まれる                                                           |
| 2026-09-21 | トップの hero を逆向きに流れる 3 段の帯 `marquee-rows` にする                                                        | スクロールなしで成果物の幅を 1 画面で伝えられる                                                               | `mosaic-reveal` は登場の 1 回しか動かない。`depth-tilt` は精密ポインタ以外で静止した壁になる                                                                   |
| 2026-09-21 | Catalog 自身の一覧とボタンに採用済みの Card と Button を使う                                                         | 見本と実際の使われ方が食い違わず、不具合を先に見つけられる                                                    | Card を Catalog 側へ複製すると採用実装と差分が生まれる                                                                                                         |
| 2026-09-21 | 詳細ページの題字に既存 status から導いた `WIP` の印を付ける                                                          | 新しい項目を足さずに未確定を見分けられる                                                                      | frontmatter に `wip` を足すと status と二重管理になる                                                                                                          |
| 2026-09-21 | Components は Button だけを本文に直接載せ、`pill-action` を採用する（後に詳細ページへ）                              | 採用実装の共有で差分を防げる                                                                                  | 3 Experiment を iframe 一覧に残すと掲載範囲に合わない                                                                                                          |
| 2026-09-21 | Components を部品ごとの詳細ページと見本カード一覧にする                                                              | 一覧の長さが部品数だけで決まり、URL で個別に共有できる                                                        | 本文直載は一覧が長くなる。iframe 詳細は内部スクロールが戻る                                                                                                    |
| 2026-09-21 | Components topic の domain に `layout` を足す                                                                        | Card を探す人は Button と同じ Components を開く                                                               | Card に `forms-input-ux` を書くと分類が事実と食い違う。Card 用の topic は探す場所が増える                                                                      |
| 2026-09-23 | Works に Motion を戻し、画面入場に `blur-focus` を採用して motion token を足す                                       | 画面表示の動きは Catalog 自身に採用するもので、成果物と実装の正本が一致する                                   | token の実演だけでは Tokens 画面と重なる。Experiment を経ずに入れると却下理由を記録できない                                                                    |
| 2026-09-25 | Icons と Motion を `catalog-works-layout` の `quiet-sections` と `motion-tiles` に揃え、成果物の見出しから日付を外す | Colors と Components と部品の語彙が揃い、成果物を一覧を挟まずに見られる。利用者が日付は一切いらないと判断した | `feature-cards` と `card-index` は一覧を挟み操作が増える。Motion の `motion-stage`、`motion-scrub`、`motion-in-context` は Icons と違う画面の型になる          |
| 2026-09-25 | 詳細ページのパンくずと live 見本の説明から日付を外す                                                                 | 利用者が詳細ページからも日付を外すことを求めた                                                                | 詳細ページだけ日付を残す案は、一覧から外した判断と食い違う                                                                                                     |
| 2026-09-25 | マークを点付きの `nu-dot` に替え、ホーム大見出しでは線を引いて点を落とす                                             | 利用者がリールの IDENTITY 場面のマークと動きを採用した。語と同時に始め、読む内容を待たせない                  | サイドバーの題字も動かす案は、全画面に常に出るので数十回見ることになる。見出しの前にロゴを静止させる従来の判断は、利用者の採用で置き換えた                     |
| 2026-09-25 | 題字とホーム大見出しの文字列を、マークと同じ作図の wordmark `caps-period` に替える                                   | マークと文字列を 1 つの規則（字画 4、round cap、円弧の接線）で組み、句点の赤い点がマークの点と呼応する        | 小文字で i の点を赤くする `lower-tittle` は、マークの点と i の点が同じ高さで並んで競る。サイドバーの題字も動かす案は、全画面に常に出るので数十回見ることになる |
