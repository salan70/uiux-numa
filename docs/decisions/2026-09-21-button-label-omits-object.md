# ボタンのラベルは文脈で分かる対象を省く

- 状態: Accepted
- 日付: 2026-09-21
- 参照: [コアの数値 ADR](2026-09-21-guideline-core-values.md)
- 対象: `docs/guidelines/ux-writing.md`、`experiments/button/shared/Showcase.tsx`

## 背景

UX Writing の Tip「ボタンのラベルは押した後に起きる行動で書く」は、対象を含む動詞句を求めていた。
良い例は「変更を保存」「アカウントを作成」だった。
Button の見本で「保存を試す」を直す際、この Tip に従うと「変更を保存」「詳細を表示」になる。
利用者は 2026-09-21 に「保存」「詳細」を選び、Tip の側を直すと判断した。

ボタンの長さの Tip は、題名が 4〜12 字、根拠の段が 2〜8 字で食い違っていた。
「保存」は題名の下限を下回る。

## 決定

- ボタンは、押した後に起きる行動（「保存」）か、移る先の名前（「詳細」）で書く。
- 見出しや周囲の内容から対象が分かるなら、対象を省く。
- 同じ画面に対象が複数あり取り違えるときだけ、対象を含める。
- ボタンの長さの Tip を「2〜8 字に収める」に揃える。
- 並列の Tip の「操作を促す面は動詞止め」を外し、面ごとにどちらかへ揃える規則にする。

## 理由

ボタンは画面の文脈の中で読まれる。
編集画面の下の「保存」は、何を保存するかを画面が既に示している。
対象を毎回書くと、ボタンが長くなり、並んだときに役割の差より語の差が目立つ。
コア「次に起きることを言い当てる」は、文脈と合わせて予測できれば満たせる。
取り違えが起きる画面に限って対象を足せば、コアを弱めずに短くできる。

2〜8 字は、Information Architecture の Tip「入口のラベルは 2〜8 字の名詞句にする」と同じ幅である。
「保存」「詳細」のような漢語 2 字を許すには、下限を 2 字にする必要がある。

「保存」「詳細」は漢語の体言止めで、動詞止めではない。
並列の Tip が操作の面に動詞止めを求めたままだと、この決定と食い違う。
並列の Tip の目的は 1 つの面の中で型を揃えることなので、どちらの型に揃えるかは面に任せた。

## 却下した案

- 対象を含む動詞句を保つ（「変更を保存」「詳細を表示」）: 文脈で分かる対象まで繰り返し、ボタンが長くなる。
- 動詞止めに揃える（「保存する」「詳細を見る」）: 語が増えるだけで、予測できる内容は変わらない。
- 「保存」「詳細」を例外に足す: 例外は慣習が確立した単一目的のボタンに限っており、一般の操作ボタンを入れると例外が本則を上回る。

## 影響

- Button の見本は「保存」「詳細」になった。
- 同じ見本の「続ける」（動詞止め）と「削除」（体言止め）は型が揃っていない。無効状態の「利用できません」は行動ではなく状態を書いている。どちらも今回は変えていない。
- 「変更を保存」は、対象が複数ある画面の良い例として残した。
