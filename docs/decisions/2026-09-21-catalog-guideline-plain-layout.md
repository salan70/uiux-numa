# 方針画面から箱をやめ、サイドバーを畳めるようにする

- 状態: Accepted
- 日付: 2026-09-21
- 参照: [方針を二次情報として載せる ADR](2026-09-20-catalog-guidelines.md)、[方針の書式 ADR](2026-09-20-guideline-format.md)、[topic-first ADR](2026-09-20-catalog-topic-first.md)
- 対象: `apps/catalog` の表示層のみ。`docs/guidelines/*.md` の書式は変えない。
- 更新: 規則の組み方、節見出しの語、行長の上限、実験欄とフッターの扱いは[規則の構造 ADR](2026-09-21-catalog-guideline-rule-structure.md) が置き換えた。

## 背景

`/guidelines/:slug` を利用者が見て 8 件の指摘を出した。

指摘は 4 つに集約できる。

- `この方針について` という節の中身が `目的` 1 項目しかなく、見出しと dt が同じことを 2 度言っていた。
- 和文の改行が語の途中で起き、読みにくい行が方針画面以外にも多く出ていた。
- タグ、図版、良い例・悪い例、例外がすべて枠と面を持ち、内容より器が先に読まれていた。
  良い例・悪い例は 2 カラムの箱で縦を大きく占め、規則本体より目立っていた。
  コアのタグは枠と hover を持つため押せる部品に見えるが、利用者は遷移を望んでいない。
- サイドバーを畳めず、15rem の桁が常に版面を削っていた。

## 決定

- 方針画面の階層を、枠と面ではなく罫 1 本、字の大小、文字色の濃淡で出す。
  タグ、良い例・悪い例、例外、図版の器から `border`、`background`、`border-radius`、`padding` を外す。
- 節の見出しを中身の名にする。`この方針について` を廃し、`目的` と `適用範囲` を別々の節にする。
- 良い例・悪い例は `bad` / `good` のラベルと本文の 2 行に畳む。
- 画面の小さなラベル（`bad`、`good`、`例外`、`実験`、`出典`）を 1 つの造形に揃え、コロンをやめる。
- コアのタグは遷移しない素の文字にする。
- 図版の標本（`.guide-figure__specimen`）だけは面を残す。罫と角丸は持たせず、平らな板にする。
- 和文は `word-break: auto-phrase` で文節の切れ目に折る。`.app-shell` へ 1 度だけ書き、継承させる。
- サイドバーを広い幅で畳めるようにする。開閉の状態は `localStorage` の `catalog.sidebar` に残す。
- 狭い幅（60rem 未満）の横帯は畳む対象にしない。開閉ボタンも出さない。

## 理由

箱は中身より先に読まれる。
規則、根拠、例、例外はもともと 1 本の読み筋なので、器で切ると読む順を器の形が決めてしまう。
罫と濃淡なら、同じ順序を占有面積を増やさずに出せる。

良い例と悪い例は規則の従属物である。
2 カラムの箱では規則本体と同じ強さで並び、1 件あたり 112px × 2 段を占めていた。
2 行に畳むと 2 行で済み、`bad` / `good` の語そのものが対であることを示す。
ラベルを英語にすると幅が揃い、本文の開始位置が 2 行で一致する。

押せない要素に押せる造形を与えない。
コアのタグは規則の出どころを示すだけで、押す先は無い。
枠と hover を外せば、見た目と挙動が一致する。

標本だけ面を残すのは、そこに実物の UI が置かれるからである。
地と同じ色だと何を見ているのか読めない。器ではなく、標本を載せる板として扱う。

`word-break: auto-phrase` は和文だけに効き、未対応のブラウザは宣言を落として既定の折返しに戻る。
段階的な適用ができるので、1 箇所に書いて全画面へ効かせられる。

サイドバーは、畳める代償より版面を全幅で読める利得のほうが大きい。
方針画面の図版と標本、Colors の帯、Tokens の表は、いずれも横幅がそのまま読みやすさになる。
状態を端末に残すのは、毎回畳み直す操作を求めないためである。
読めない環境では例外を握りつぶし、開いた状態に落とす。ナビが見えているほうを既定にする。

## 却下した案

- 図版だけ枠を残す: 器が 1 種類だけ残ると、なぜそこだけ枠があるのかが読めない。標本の面で足りる。
- 良い例・悪い例を折りたたみにする: 読む量は最小になるが、規則を理解するのに操作が 1 回増える。例は規則と同時に読むものである。
- 良い例・悪い例を 2 カラムのまま余白だけ削る: 横並びの対比は残るが、縦の占有は半分にしかならない。2 行なら 2 行で済む。
- ラベルを `良い例` / `悪い例` のまま残す: 和文 3 文字は幅が揃うが、本文と同じ字種なのでラベルとして立たない。
- サイドバーをアイコン幅の桁に縮める: 現在地が常に見える利点はあるが、このナビは日本語のラベルが主体で、11 面分のアイコンを新たに作ることになる。
- 狭い幅を重なるドロワーにする: 横帯は 1 行しか占めておらず、畳む理由がない。
- 開閉ボタンを本文側だけに置く: 閉じるときと開くときで押し先が画面の反対側へ飛ぶ。開いている間は題字の横に置く。
- 開閉の状態を URL の query に載せる: 撮影の再現性は上がるが、リンクを共有するたびに相手のナビの状態まで決めてしまう。
- `word-break` を方針画面だけに当てる: 指摘は「他にも同様の箇所がたくさんある」であり、画面ごとに足すと漏れる。

## 覆した判断

`apps/catalog/src/components/Layout.tsx` の「畳む操作を置かないので、現在地を探す操作が要らない」を覆す。
現在地を探す操作が要らないのは事実だったが、全幅で読みたい場面があることを画面で確かめたため、畳める側を採る。
畳んでも本文の縦位置は動かない（開くボタンは版面の上余白へ絶対配置する）。

## 影響

- 変更は `apps/catalog` だけに入れる。
  `experiments/catalog-editorial/variants/topic-first` は段階 A10 時点の記録として凍結し、この変更を写さない。
  以降、Experiment と公開面の見た目は一致しない。
- 配色 `sumi` では `--cat-muted` と `--cat-accent-text` が同値になるため、`bad` と `good` のラベル色が同じになる。
  区別は語そのものが持つ。色だけに頼らない方針（[方針を二次情報として載せる ADR](2026-09-20-catalog-guidelines.md)）と同じ立場である。
- サイドバーを畳むと配色と明暗の選択も隠れる。切り替えるには 1 度開く。
- このリポジトリで `localStorage` を使うのはこれが最初である。読み書きは例外を握りつぶす。
