# 規則を good と bad の対にし、図版を廃止する

- 状態: Accepted
- 日付: 2026-09-21
- 参照: [規則の構造 ADR](2026-09-21-catalog-guideline-rule-structure.md)、[方針を二次情報として載せる ADR](2026-09-20-catalog-guidelines.md)、[24 役割の ADR](2026-09-20-catalog-material-color-roles.md)
- 出どころ: [guideline-rule-structure](../records/guideline-rule-structure/README.md)

## 背景

規則ブロックを bad / good の 2 行に畳んだあとも、利用者の評価は
「各情報がぱっとみで何を表しているか、どういう構造かがわからない」だった。
bad と good だけがラベルを持ち、分類、根拠、例外、出典は素の段として同じ強さで積まれていた。

[guideline-rule-structure](../records/guideline-rule-structure/README.md) で
役割の示し方を軸にした 4 案（`labelled-column`、`heading-blocks`、`meta-aside`、`contrast-pair`）を
実データで組み、利用者が `contrast-pair` を選んだ。

## 決定

- 規則 1 件を 4 段に固定する。**題名 + 適用** → **なぜ（根拠）** → **good ｜ bad** → **例外**。
- good を左、bad を右に置き、同じ幅の桁に収める。境は罫 1 本で、溝の中央に置く。
- `foundation` / `module` は規則の題名のすぐ横に置く。
- 結び付くコアを画面に出さない。
- 規則ごとの出典（参考リンク）を画面に出さない。文書全体の Sources の節は残す。
- 図版を廃止する。`docs/guidelines/*.md` の `- 図:` の項目、解析器の `figureKey` と
  `VALID_FIGURE_KEYS`、`apps/catalog/src/components/figures.tsx` をすべて削除する。
- good と bad の語に、24 役割の `--color-success` と `--color-error` を当てる。
  `--cat-good` と `--cat-bad` として受ける。

## 理由

規則の中で唯一の対は good と bad である。
対を桁の形にすると、残りの 3 段が対の外にあることが位置で決まる。
段が 4 つに固定されるので、例外や図版の有無で規則ごとに形が変わらなくなる。

good を先に読ませるのは、bad から読むと正しい形に辿り着くまで 2 度読むことになるからである。

適用は題名の従属物である。
「どのプロジェクトで守るか」は題名と対で読む情報なので、同じ行に置く。

結び付くコアは、規則を使う側の判断を変えない。
コアと Tips の対応は正本が持てばよく、規則を読む導線に挟む理由がない。

図版は規則を特定の画面の見た目へ縛っていた。
規則が扱うのは場面であって、タブが何 px 動くかではない。
キャプションは規則の bad / good の文とほぼ同じことを書いており、標本を持つ規則だけ縦が伸びて対の高さも揃わなかった。
図版は表示のための道具であり、正本に残す理由がない。ここが出どころ（`実験:` と `出典:`）との違いである。
出どころは判断の記録なので正本に残し、画面には出さない。

色は意味の役割から引く。
画面の強調色（`--cat-accent-text`）を good に使うと、配色を切り替えたときに
「その配色の色」と「良し悪し」が同じ色で出て読み分けられない。
`--color-success` と `--color-error` は 10 配色 × ライト / ダークのすべてで
背景に対し 5.57:1 以上あり、AA を満たす。
色だけに頼らないよう、`good` / `bad` の語そのものも残す。

## 却下した案

判断者は利用者である。判断日は 2026-09-21 である。
4 案とも実データで組んだ画面を見た上で、評価を経ずに却下した。

- `labelled-column`（すべての行にラベルの桁を 1 本通す）: 拾い読みには最も強いが、
  ラベルの桁ぶん本文が右へ寄り、役割が増えるとラベルの語も増える。
- `heading-blocks`（役割を小見出しとして立てる）: 通読の順は最も明確だが、
  見出しと本文で 2 行使うため 1 件の縦が最も長く、8 件並ぶと画面数が増える。
- `meta-aside`（分類と出典を右の細い桁へ出す）: 本文は 1 本の読み筋になるが、
  桁が 2 本要り、狭い幅ではメタが本文の下へ落ちて結局縦に積まれる。
- 標本だけ残して図版のラベルとキャプションを落とす: 標本を持つ側だけ桁が伸び、対の高さが揃わない。
- `- 図:` を正本に残し、描画だけをやめる: 参照先のない鍵が正本に残る。
  出どころと違い、図版は記録ではない。

## 影響

- 代償として、good と bad の行長が半分になる。44rem 以下では対を縦に積む。
- 正本の `- 図:` を 9 件削除した。`experiments/catalog-editorial/variants/topic-first` は
  図版を描く実装のまま残るが、正本に鍵が無くなったので図版は出ない。
  この Experiment は段階 A10 で凍結済みであり、追従させない。
- `experiments/guideline-rule-structure` は Catalog 自身を比べる Experiment なので、
  `UNCATEGORIZED_SLUGS` に入れて公開ナビへ出さない。
- 狭い幅の `@media (width <= 44rem)` は、この画面のためだけの 5 つ目の breakpoint である。
  既存は 40rem / 60rem / 72rem で、揃えると対が 1 行 13 字ほどになる。
  breakpoint を token にするかは別途決める。
