# 画面文言の日本語表記を Japanese Notation として定める

- 状態: Accepted
- 日付: 2026-09-22
- 参照: [UX Writing を部品と状態の文言に絞って組み直す](2026-09-22-ux-writing-redesign.md)、[コアに主題全体へ効く数値を書き、UX Writing の区切りをコアへ上げる](2026-09-21-guideline-core-values.md)
- 対象: `docs/guidelines/japanese-notation.md`、`docs/guidelines/ux-writing.md`、`apps/catalog/src/content/guidelines.ts`、`docs/guidelines/README.md`

## 背景

UX Writing は表記を別の文書で扱うと書くが、受け皿が無かった。
[UX Writing 組み直し ADR](2026-09-22-ux-writing-redesign.md) は、画面文言の表記の文書が未作成だと影響に残している。
設計文書の表記は concise-writing が定める。
正本は `writing-standard.md` である。
画面文言は、その基準の対象外だった。

Catalog と Experiment の文言には、次の揺れがある。

- 日付はドット形式と月日と年月日と曜日付きが混在する。
- スラッシュは「UI/UX 沼」と「UI／UX 沼」が混在する。
- 中点は `・`（U+30FB）と `·`（U+00B7）が混在する。
- 一覧の説明文は句点の有無が混在する。
- 同じファイルに「第三色」と「第 3 色」がある。
- 「が無い」が 1 件あり、他は「がない」である。
- 外来語は「ブラウザ」「ポインタ」「パラメータ」のように長音を省いて揃っている。
- 全角英数字と全角の「！」「？」と半角カナと「，」「．」と「下さい」は 0 件だった。
- 範囲の「〜」と省略の「…」と、単位を数字の直後に書くことは一貫している。

進め方は UX Writing と同じである。
広く洗い出したあと、2026-09-22 に 3 巡で収束させた。

## 決定

### 輪郭

- 空白と括弧と単位は writing-standard と同じにする。画面にはその規則をそのまま書く。
- 日本語と英数字の間に空白を入れる。
- 括弧の内外には空白を入れず、単位は数字の直後に書く。
- 空白と括弧と単位の規則は Tips に置かず、目的に書く。
- 対象は画面に出る文字列すべてとする。日時と数値の形式も含める。
- かなで書く語の一覧は作らず、Guideline には代表例だけ置く。

### コアと分岐

- コアは 3 件にする。優先順は次のとおり。
  1. 環境に依存しない文字で書く
  2. プロダクト全体で 1 つの形に揃える
  3. 見てすぐ読める漢字とかなを選ぶ
- 慣用（外来語）は 3 件目に畳む。
- 疑問符と感嘆符は全角の「？」「！」にする。
- 外来語の語尾の長音は付ける（ブラウザー、ユーザー）。
- 日付は `2026.09.22` に統一する。時刻は 24 時間の `12:05` にする。

### Tips

- 文の記号は全角、英数字に付く記号は半角にする。
- ラベルと値のコロンは、writing-standard と同じ半角と空白にする。
- 例は `最終更新: 2026.09.22` である。
- 範囲は「〜」（U+301C）、省略は「…」を 1 つにする。
- 補足の括弧は（）、引用と入力値は「」にする。半角の `()` は英字の内部だけに使う。
- Tips は 8 件で、すべて `foundation` にする。
  1. 実質の意味を持たない語はかなで書く
  2. 数えられる数は半角の算用数字、置き換えられない数は漢数字で書く
  3. 日付は `2026.09.22`、時刻は 24 時間の `12:05` で桁を揃える
  4. 句点は文の終わりだけに付け、名詞句には付けない
  5. 疑問符と感嘆符は全角で書き、直前に空白を入れない
  6. 文の記号は全角、英数字に付く記号は半角で書く
  7. 外来語は語尾に長音を付け、定着した形で書く
  8. 環境依存文字と代用記号を使わない

## 理由

### 継承

文書と画面で基準が 1 つになる。
UX Writing が 1 文 50 字を継承したのと同じ判断である。
Catalog には concise-writing の名を出さない。
規則そのものを目的に書く。

### 空白

[Microsoft のスタイルガイド](https://download.microsoft.com/download/8c2f9704-5bd0-4422-8d29-58afb0146545/jpn-jpn-StyleGuide.pdf) の 4.1.11 は、全角と半角の間に半角空白を入れる。
既存の画面文言も、ほぼこの形になっている。

### コアの順

半角の数字は、形が揃っていてもこの基準では許さない。
環境に依存しないことを、揃えることより上に置く。

### 疑問符と感嘆符

[JTF 日本語標準スタイルガイド](https://www.jtf.jp/pdf/jtf_style_guide.pdf) は記号類を全角にする。
[SmartHR の記号の表記](https://smarthr.design/products/contents/idiomatic-usage/symbol/) も「？」「！」を全角にする。
句読点と同じ幅で揃う。

### 長音

語尾の長音は、公用文と JTF と Microsoft と SmartHR が一致する。
`-ty` と `-ry` も公用文に従い、カテゴリーのように長音を付ける。

### 日付

`2026.09.22` は利用者の指定である。
外部資料にこの形式は無い。
数字の並びだけで表すので、助数詞の空白規則の例外を作らない。
ゼロ埋めで幅が揃う。
年と月と日の順は ISO 8601 と同じで、文字列の比較で並べ替えられる。
スラッシュを含まないので、パスと見分けられる。
読み上げが区切りの「点」を読む可能性がある。

### 括弧

writing-standard は半角括弧を外側の空白付きで許す。
画面の補足は（）に揃える。
これが、継承した基準と画面で違える点の 1 つである。

## 却下した案

- 日本語と英数字の間に空白を入れない。JTF と SmartHR の方針だが、concise-writing と既存実装から離れる。
- 画面の表記を設計文書と独立に決める。文書と画面で基準が分かれる。
- 用字一覧を別ファイルにする。代表例で足り、一覧の維持が主題から外れる。
- コアを 4 件にし、慣用を独立させる。外来語は 3 件目のコアで足りる。
- 疑問符と感嘆符を半角にする。Microsoft と旧 UX Writing の例だが、記号類は全角に揃える。
- 長音を省略する。JIS の旧慣習であり、出典を置けない。
- `-y` の語尾に長音を付けない。SmartHR の方針だが、利用者は 2026-09-22 にこの案を選ばなかった。
- 日付を年月日、ISO 8601、スラッシュで書く。利用者は `2026.09.22` を指定した。
- 範囲を「から」で書く。Microsoft の方針だが、狭い面で長くなる。
- 日本語に接する記号をすべて全角にする。コロンが writing-standard と食い違う。

## 出典として使えなかったもの

- SmartHR の `ui-text/notation/` は 404 だった。用字用語は `idiomatic-usage/` 配下を出典にした。
- aka.ms の短縮 URL は PDF へ 301 する。出典は到達先の URL にする。

## 採用

2026-09-22 に利用者が確認し、`status` を `adopted` にした。

## 影響

- UX Writing の確認の例 2 箇所を、全角の疑問符に直す。
- UX Writing の境界から Japanese Notation へリンクする。
- `GUIDELINE_ORDER` に `japanese-notation` を足す。
- ガイドラインの文書一覧にも同じ slug を足す。
- 実装は変えない。`work.ts` のコメント誤記は悪い例として残す。
- `Sidebar.tsx` の全角スラッシュも悪い例として残す。
- 句点の混在と長音の省略も、悪い例として残す。
- 常体と敬体の混在は UX Writing の範囲であり、今回は未対応である。
- 押せない状態の「利用できません」も、今回は未対応である。
