## 背景

Issue #17 は、ガイドライン 7 本と運用文書を AI が専門観点でレビューした結果を R01〜R20 に集約した。
基準 commit `5f35024` 以降、対象の文書は変わっていない。
各指摘を本文、関連 ADR、form-inline-validation の記録、原典と照合し、妥当性を判定した。

## 決定

判定の方針は次の 3 つにする。

- 誤記、原典と食い違う主張、本文内の矛盾は直す。
- adopted 文書では採用済みの値と語形を変えず、条件と例外の明確化に留める。
- 新しい記録枠や将来の要件は足さない。

## 理由

### 採用済みの値を変えない

2〜8 字、1 文 50 字、`2026.09.22`、名詞ラベル、1〜2 画面は、いずれも利用者が 2026-09-21 から 2026-09-22 に選んだ値である。
指摘の多くは値そのものではなく、値が普遍的な閾値に読めることや、例外の欠落を問題にしていた。
値を残して条件と例外を書けば、採用の判断と指摘の両方が成り立つ。

### 応答時間

[NN/g: Response Times](https://www.nngroup.com/articles/response-times-3-important-limits/) は、0.1 秒を即座に反応したと感じる目安、1 秒を思考の流れが途切れない目安とする。
超えると因果が分からなくなる境界ではない。
旧出典の 10 ヒューリスティクスは数値の根拠ではなかった。

### WCAG の数値

[Contrast Minimum の解説](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) は、計算値を丸めない（4.499:1 は満たさない）とする。
14pt と 18pt を約 18.5 CSS px と 24 CSS px に換算する。
背景画像上の文字が比を満たさない場合を失敗例 F83 に挙げる。
[Target Size Minimum の解説](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) は 24×24 CSS px を下限とし、間隔や同等の操作などの例外を持つ。
間隔の例外は、小さな対象の円が他の対象にも、他の小さな対象の円にも交差しないことを条件にする。
[Resize Text の解説](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) の例外は字幕と文字画像だけで、表や地図を除外しない。
2 次元の配置の例外は Reflow だけにある。

### モーダル

[WAI-ARIA APG: Dialog (Modal) Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) は、名前、初期フォーカス、閉じたときの復帰先を要件にする。
`dialog` 要素は `showModal()` で開いたときだけ背後を不活性にする。

### コアの比較文

States & Feedback の「結果の正確さより、因果が途切れないこと」は、受付通知と結果通知が両立するのに対立させていた。
書式が全コアに比較文を求めたことが原因なので、比較文は実際に衝突するときだけ書く形にした。
既存コアの比較文は、指摘の対象になったものだけを直した。

### Design Principles から除いた文

token の個数、Issue #7、Issue #11、breakpoint の作業範囲は、視覚構成を判断する場面で使わない。
Issue のスコープは各 Issue と [Design Principles 再設計 ADR](2026-09-22-design-principles-redesign.md) の範囲で管理する。

## 却下した案

- 入口ラベルを名詞以外にも広げる（R09）: 採用済みの判断であり、一覧で形式を揃える理由は今も成り立つ。目的別の操作はボタンとして UX Writing が扱う。
- 「その他を作らない」を緩める（R09）: 分類が増える懸念は、行き先の分類を足す判断を書き手に求める現行の規則で扱える。
- UX Writing のコア見出し「断定しない」を改める（R12）: 本文が既に「確かめた範囲と文言の強さを合わせる」と定めており、完了した事実を曖昧にする読み方は生じない。
- 日時の意味とタイムゾーンの規則を足す（R15）: 現時点で扱うプロダクトが無く、将来の要件に備えた規則になる。
- 根拠を外部規範、他社の規約、観察、選好に分類する記録枠を足す（R20）: 既存の「出典は規則が文献の主張であるときに書く」を守れば足りる。
- 出典を複数件にし、解析器を改める（R20）: 画面に出典を出さないため、1 件を選び残りを根拠の段か ADR に置けば記録は辿れる。
- 全ガイドラインを貫く優先順位表を作る（R19）: 文書をまたぐ衝突は、対象、条件、根拠を照合して解く。

## 影響

- Accessibility、Color、States & Feedback、Design Principles のコア見出しが変わった。`- コア:` の参照も揃えた。
- Color のコアは 5 件から 4 件になり、無彩色中心の Tip は `module` に移った。
- UX Writing、Japanese Notation、Information Architecture は `adopted` のままである。採用済みの値は変えていない。
- draft 文書の `status` は変えていない。
- Catalog の表示仕様と解析器は変えていない。
- 解析器のテスト（`guidelines.test.ts`）の見本は独立した入力なので、旧コア名のまま残した。
- c679af1 の再レビューを受け、同日に 3 点を補った。
  ターゲット間隔の例外に円どうしの条件を足し、2 次元の配置の例外を Reflow に限った。
  Information Architecture のコアにも、実体と主分類は 1 つ、入口は複数可という区別を書いた。
