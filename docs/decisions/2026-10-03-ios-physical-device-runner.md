# iOS の試作を実機で比較する

- 状態: Accepted
- 日付: 2026-10-03
- 参照: [iOS 実行基盤](2026-09-28-ios-runner.md)

## 背景

MyRecipee の UI 試作を、利用者のペアリング済み iPhone でワイヤレスに確認したいという依頼があった。
既存の実行基盤はシミュレータ専用で、署名を無効にしていた。
一覧と variant の実装は実機でもそのまま利用できる。

## 決定

`just ios-device-build <device-id> <team-id>` と `just ios-device-run <device-id> <team-id> [args...]` を追加する。
Xcode の自動開発署名を使い、チームと端末の ID は引数で指定する。
個人のチーム設定、端末 ID、証明書をリポジトリへ配布しない。
既定のシミュレータ用設定を保ち、署名を実機ビルドのコマンドで上書きする。
実機成果物は `platforms/ios/build-device/` に置き、Git の対象外にする。
`devicectl` でペアリング済み端末へインストールし、起動引数なしで variant 一覧を開く。
一覧から選んだ variant は画面上部の「一覧へ戻る」で閉じる。
実機でステータスバー中央の長押しが反応しなかったため、safe area 内に 44 pt 以上のボタンを常設する。
ボタンは案の操作と重ならないよう、一覧から開いたときだけ専用の行に置く。
`-variant` で直接起動する撮影には戻る行を加えない。
ブレークポイントを使う場合は、生成した Xcode プロジェクトを開き、同じ開発チームと実機を選んで Run する。

## 却下した案

- Team ID を `project.yml` に固定する: 個人の設定を配布し、別の開発チームで再利用できなくなる。
- TestFlight を先に用意する: 手元のペアリング済み端末での比較には、配布と審査の基盤が不要である。
- MyRecipee 本体へ比較 UI を組み込む: 試作を独立したアプリで確認するという目的に合わない。
- ステータスバー中央の長押しで一覧へ戻す: 実機で反応せず、操作の存在も画面から分からない。

## 影響

従来の ADR の「シミュレータでだけ動かし、署名しない」を、実機起動のコマンドに限り置き換える。
実機用のビルドには、Xcode の開発署名と利用者による端末のペアリング、開発者モードが必要になる。
Flutter の Experiment は SwiftUI の runner に収録しない。
