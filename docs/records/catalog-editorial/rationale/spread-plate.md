# spread-plate の決定

> 却下（利用者の判断、2026-09-20）。
> 評価を経ずに先へ進めない判断をした。理由は [README の Rejected reasons](../README.md#rejected-reasons) にある。
> 以下は紙の質感をやめる方向修正より前の記録であり、造形もその時点のままである。

図録の見開き。
1 作品に 1 見開きを与え、ホストは無彩のマットに徹する。
実装は variants/spread-plate/。

この案だけが欧文セリフの追加を軸に持つ。
採ると `docs/decisions/2026-09-19-typography-foundation.md` の「LINE Seed で和欧を揃える」判断を、Catalog の display 用途に限って覆すことになる。

## 決定

| 決定         | 値                                                             | 意図                                                   | 根拠                                                                                                  | 却下案と理由                                                                                                |
| ------------ | -------------------------------------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| IA           | 1 作品 1 見開き。トップは表紙 + 見開きの連続を縦送り           | 標本を画面で最大にする                                 | 「一覧は preview を先に、詳細は live specimen を先に」の極端な形。説明が図版より前に来ない            | カード格子のトップ。均一な格子で、いまの不満の中心に戻る                                                    |
| ナビ         | 右上の「目次」Drawer だけ                                      | 常時表示のナビを置かず、面を図版に明け渡す             | 見開きが主役なので、恒常的な chrome を最小にする                                                      | 上部の固定ナビ。見開きの上端が常に削られ、1 作品 1 画面が成立しない                                         |
| URL          | `/`、`/contents`、`/plates/<slug>`                             | 図録の語彙に揃える                                     | Plate 番号と目次で構成される図録の構造をそのまま URL にする                                           | `/works/<slug>`。号の案が使う語彙。案ごとに変えて比べる                                                     |
| グリッド     | 左面 4 列が文字、右面 8 列が図版。作品ごとに左右を交互         | 図版を広い側に置く                                     | 当初 5 : 7 で組んだが、配色の表が右面に収まらず参照の列が 1 文字ずつ折り返した。実測して 4 : 8 に変更 | 5 : 7。表が収まらない／6 : 6。図版と文字が同じ幅になり、どちらが主役か読めない                              |
| 左右の交互   | 作品ごとに入れ替える                                           | 同じ配置が続くと見開きの区切りが消える                 | 縦送りで同じ配置が並ぶと、見開きではなく縦に流れる一覧に見える                                        | 固定配置。実装は単純だが、見開きという単位が読めなくなる                                                    |
| 文字階梯     | 0.75 / 0.8125 / 0.9375 / 1.0625 / 1.75 / 3rem                  | 主役は図版なので、題名を大きくしない                   | 題 1.75rem は token の title 1.5rem をわずかに超える値。図版より前に出ない上限                        | 巨大見出し。号の案が担当する軸。図録で題名が図版より大きいと、解説書になる                                  |
| 欧文セリフ   | 図版番号、数値、銘板だけに使う。和文は LINE Seed のまま        | 400 / 700 しかない和文に、細いセリフの数字で対比を作る | 数字と英字は和文と字形の系統が違うので、書体を分けても混植の違和感が出にくい                          | 和文もセリフ（明朝）にする。本文用の和文セリフを self-host すると転送量が数 MB になる                       |
| 書体の候補   | Fraunces / Newsreader / Source Serif 4。いまは系統書体で仮組み | 実物を載せる前に、足すこと自体の可否を決めてもらう     | すべて OFL で self-host できる可変セリフ。数字と基本ラテンに subset すれば数十 KB に収まる            | 先に 1 つ入れる。ADR と衝突する変更を、判断の前に既成事実にすることになる                                   |
| 余白         | 2 / 1.5 / 2.5 / 8rem                                           | 図版の内マットを最大の余白にする                       | 額装は余白そのものが機能する。内マット 2rem が図版と縁の間の最小                                      | 内マットなし。図版が縁に接し、額ではなく箱になる                                                            |
| 配色         | 地 / マット / 墨 / 解説 / 罫 の 5 role。差し色を持たない       | 色を持つのは作品だけにする                             | 白練、胡粉色、墨、石板色、灰色。地とマットの 2 段の白で、影なしに奥行きを作る                         | 差し色を 1 つ持つ。どの作品を載せても、その色と作品の色が競合する／影で奥行きを作る。影は作品の色を濁らせる |
| 配色切替     | 図版の面と標本にだけ効かせる                                   | マットは変わらず、作品だけが色を持つ                   | 美術館の壁は展示で変えない                                                                            | ホスト全体に適用。無彩のマットという位置が消える                                                            |
| 焦点の示し方 | 墨の 2px 輪郭 + 3px のオフセット                               | 差し色がないので、輪郭と間で示す                       | 墨は地に対して 12.75:1。3:1 を大きく超える                                                            | 差し色の輪郭。差し色を持たない判断と矛盾する                                                                |
| 部品の造形   | 小さな丸囲みと矢印。角丸 999px                                 | 図録の記号に寄せる                                     | 図版番号や送りの記号は、図録では丸や三角の小さな印である                                              | 角丸 0 の矩形。雑誌の案と造形が重なり、比較の差が消える                                                     |
| 標本の額装   | マットの余白と 1 本の罫で額装し、下に Plate キャプション       | 影を使わずに額を作る                                   | 影は作品の色に影響する。余白と罫なら、どの配色の作品を載せても濁らない                                | 影付きの浮いたカード。`playful-chroma` と同じ問題に戻る                                                     |
| motion       | 見開き間は `scroll-snap`。Drawer は 240ms の transform         | 送りの単位を見開きに固定する                           | `scroll-snap` は入力に追従するので、動きが操作を妨げない。`prefers-reduced-motion` では即時にする     | 見開きごとのフェード。縦送りの途中で文字が消え、読んでいる最中に内容が失われる                              |
| 読み込み     | iframe は遅延読込にする                                        | 10 見開きを縦に並べると、iframe が 10 台同時に立つ     | 同一 origin の iframe は 1 台ごとに React を起動する                                                  | 全件即時読込。初回表示が重くなる                                                                            |

## 代償

- 一覧性が 4 案で最も低い。目次を開かないと全体が見えない。
- iframe を縦に並べるため、遅延読込が必須になる。
- 欧文書体を足すと転送量が増え、既存の ADR と衝突する。
