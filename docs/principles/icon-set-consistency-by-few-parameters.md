## 仮説

アイコンの組は、少数のパラメータ（線幅、端点と角、live area）を全要素で 1 つの値に固定すると、組として揃う。
パラメータが多い語彙（塗りの面積、accent の形と面積）を使うと、同じ手間では揃わない。
揃った組は、落ち着いた几帳面な印象を生む。

## 適用条件

- 成果物: 2 個以上で 1 組として使うアイコン。単体のロゴや挿絵には当てはまらない。
- プロダクト: 個人開発のプロダクト全般。UI の中で文字と並ぶアイコン。
- 表示サイズ: 最小 16px から、投影の 96px まで。

## 必要な値

この候補の値であり、普遍の正解ではない。
別のプロダクトでは、同じ手順で値を決め直す。

1. 語彙を 1 つ選ぶ。線画、塗り、2 色のどれかにする。組の中で混ぜない。
2. 線画を選んだ場合、固定するパラメータは次の 3 つにする。
   - 線幅: 1 つの値。24 の viewBox なら 2。1 つの図形の中でも混ぜない。
   - 端点と角: `stroke-linecap` と `stroke-linejoin` を root で 1 回だけ指定する。要素側で上書きしない。
   - live area: viewBox に対する padding を 1 つの値にする。24 なら 2。
3. 座標は線幅の偶奇で刻みを決める。偶数幅は整数座標、奇数幅は 0.5 刻みにする。
4. 塗りの語彙を選んだ場合、上の 3 つに加えて塗りの面積を揃える必要がある。面積は形ごとに測って比べる。
5. 2 色の語彙を選んだ場合、さらに accent の形と面積の規則を先に決める。位置（意味の要点）だけを決めても揃わない。

## 作例

良い例は `experiments/class-tech-icons/variants/line-round/`。
8 個すべてで root の属性が 1 文字も違わず、座標は 27 種すべて整数だった。
24px の外形は 16〜20 に収まり、4 案で散りが最小だった。

悪い例は同じ Experiment の `variants/solid/` と `variants/duotone/`。
`solid` は 24px の外形が 14〜22 と散り、外形面積の最大と最小の比が 1.96 になった。
開いた形と塊の見かけの重さの差は、塗りの語彙では原理的に残ると制作者自身が記録している。
`duotone` は accent が同じ役割に対して 7 種類の形を取り、96px での赤の面積が 4.1 倍開いた。

preview は `experiments/class-tech-icons/previews/compare-final-24.png` と `compare-final-96.png`。

## 例外

- 単体で使うマーク（ロゴ、favicon）には当てはまらない。組がないので揃える相手がない。
- 投影を最優先する場面では、塗りの語彙のほうが強い。`solid` は 96px で見出しの 1.95 倍と 4 案で最も主役になった。手元の 20px では逆に文字と競合する。用途を分けるなら、この原則は用途ごとに適用する。
- 意味の伝達はこの原則の対象外である。揃った組でも比喩が合わなければ意味は届かない。

## 検証結果

- `class-tech-icons`（2026-09-19）: 4 案を designer と implementation の 2 観点が consistency で判定した。線画の 2 案が「良い」、塗りと 2 色の 2 案が「課題あり」または「許容」だった。制作の手間は 4 案でほぼ同じ（反復 2〜3 回）である。
- 未検証: 他のプロダクト、他のサイズ帯（8px、128px 以上）、線画以外の語彙で同じ手間をかけた場合。
- 未検証: 揃った組が「落ち着いた几帳面な印象」を生むかは、利用者の選択（`line-round` の採用）から推測したもので、印象を直接確かめていない。
