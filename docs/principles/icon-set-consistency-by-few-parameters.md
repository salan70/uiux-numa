## 仮説

アイコンの組は、少数のパラメータ（線幅、端点と角、live area）を全要素で 1 つの値に固定すると、組として揃う。
パラメータが多い語彙（塗りの面積、accent の形と面積）を使うと、同じ手間では揃わない。
揃った組は、落ち着いた几帳面な印象を生む。

## 適用条件

- 成果物: 2 個以上で 1 組として使うアイコン。単体のロゴや挿絵には当てはまらない。
- プロダクト: 個人開発のプロダクト全般。UI の中で文字と並ぶアイコン。
- 表示サイズ: 最小 16px から、投影の 96px まで。

## 必要な値

この候補の値であり、普遍の正解ではない。
別のプロダクトでは、同じ手順で値を決め直す。

1. 最小の表示サイズを先に決める。線幅と座標の刻みは、このサイズで整数ピクセルになる値から逆算する。
2. 語彙を 1 つ選ぶ。線画、塗り、2 色のどれかにする。組の中で混ぜない。
3. 線画を選んだ場合、固定するパラメータは次の 4 つにする。
   - 線幅: 1 つの値。最小サイズで整数ピクセルになる値にする。24 の viewBox で最小 24px なら 2、最小 16px なら 1.5 を選ぶ。1 つの図形の中でも混ぜない。
   - 座標の刻み: 最小サイズの倍率を掛けて整数ピクセルになる値にする。線の中心は 線幅 / 2 + 刻み × n に置く。24 の viewBox で最小 16px なら 0.75 刻みになる。
   - live area: viewBox に対する padding を 1 つの値にする。24 なら 2。
   - 内側の最小隙間: 線幅と同じ値以上にする。線幅 2 で中空の直径が 2 を下回ると、16px で塊になる。
4. 端点と角は root で 1 回だけ指定し、要素側で上書きしない。ただしこれは差を生む条件ではなく前提である（下の検証結果を参照）。
5. 塗りの語彙を選んだ場合、上に加えて塗りの面積を揃える必要がある。面積は形ごとに測って比べる。
6. 2 色の語彙を選んだ場合、さらに accent の形と面積の規則を先に決める。位置（意味の要点）だけを決めても揃わない。

## 作例

良い例は `experiments/class-tech-icons/variants/line-round/`。
8 個すべてで root の属性が 1 文字も違わず、座標は 27 種すべて整数だった。
24px の外形は 16〜20 に収まり、4 案で散りが最小だった。

悪い例は同じ Experiment の `variants/solid/` と `variants/duotone/`。
`solid` は 24px の外形が 14〜22 と散り、外形面積の最大と最小の比が 1.96 になった。
開いた形と塊の見かけの重さの差は、塗りの語彙では原理的に残ると制作者自身が記録している。
`duotone` は accent が同じ役割に対して 7 種類の形を取り、96px での赤の面積が 4.1 倍開いた。

preview は `experiments/class-tech-icons/previews/compare-final-24.png` と `compare-final-96.png`。

## 例外

- 単体で使うマーク（ロゴ、favicon）には当てはまらない。組がないので揃える相手がない。
- 投影を最優先する場面では、塗りの語彙のほうが強い。`solid` は 96px で見出しの 1.95 倍と 4 案で最も主役になった。手元の 20px では逆に文字と競合する。用途を分けるなら、この原則は用途ごとに適用する。
- 意味の伝達はこの原則の対象外である。揃った組でも比喩が合わなければ意味は届かない。
- bounding box の一致は、見かけの大きさの一致ではない。外形が揃っても、質量が中央に寄る形は小さく見える。keyline（`ICON-06`）を別に当てる必要がある。
- 比喩が 2 要素以上を含む場合、線幅と live area が 24 の viewBox で両立しないことがある。線画では要素を削るか、塗りの語彙のほうが同じ比喩を小さく詰められる。

## 検証結果

- `class-tech-icons`（2026-09-19）: 4 案を designer と implementation の 2 観点が consistency で判定した。線画の 2 案が「良い」、塗りと 2 色の 2 案が「課題あり」または「許容」だった。制作の手間は 4 案でほぼ同じ（反復 2〜3 回）である。
- `hako-feature-icons`（2026-09-19、別プロダクトでの試行）: 架空のタスク共有アプリ Hako（3 個 1 組、16〜24px）で、初版の手順に厳密に従った variant `principle-applied` を作り、既存 3 案と同じ測り方で比べた。**部分的に反証された。**
  - 支持された点: 24px の外形が 3 個とも 20×20 で完全に一致し（比 1.00）、座標は整数 22 種だけになった。プロダクト、個数、サイズ帯が違っても、外形の一致は再現した。
  - 反証 1: 初版の「固定する 3 パラメータ」のうち、root の属性の一致と要素側の上書き 0 は、4 案すべてが既に満たしていた。Skill も原則も使わない `no-skill` でも満たしている。差を生んだのは座標の刻みと外形だけで、端点と角は前提にすぎなかった。
  - 反証 2: 外形 1.00 は 3 パラメータの必要条件ではない。`with-skill` も 1.00 を達成しており、語彙を混ぜ（塗り 6 要素）、座標も整数ではない（0.75 刻み）。
  - 反証 3（最も重要）: 初版は最小の表示サイズを決めていなかった。24 の viewBox の整数座標は 16px で 2/3 倍になり、境界から外れる。線幅 2 も 1.33px になる。16px の中間 alpha 画素の割合は 89% と 4 案で最悪になり、線幅 1.5 と 0.75 刻みの `with-skill`（41%）の 2 倍を超えた。由来の Experiment が 20〜96px だったため、この穴は露出しなかった。
  - この反証を受けて、「必要な値」に手順 1（最小サイズを先に決める）と、内側の最小隙間を足した。座標の刻みの決め方も書き換えた。
- 未検証: 他のサイズ帯（8px、128px 以上）、塗りと 2 色の語彙（手順 5、6）で同じ手間をかけた場合。
- 未検証: 揃った組が「落ち着いた几帳面な印象」を生むかは、利用者の選択（`line-round` の採用）から推測したもので、印象を直接確かめていない。
- 未検証: root の属性の一致が差を生まなかったのは、4 案とも 1 組を 1 セッションで作ったためかもしれない。複数人や時期をまたぐ追加では確かめていない。
