## 目的

配色の意図を崩さず、UI の役割と状態を明瞭に伝える。
装飾的な色の多用を抑え、成果物やコンテンツそのものを主役に立たせる。

## 適用範囲

画面全体のカラーパレット、トークン定義、面と線の配色に適用する。
イラストやロゴなど、独自の表現色を持つグラフィック素材は対象外とする。
コントラストの閾値と、色だけで意味を伝えない規則はアクセシビリティのガイドラインが正本とする。

## 規則

### 色は直接の値ではなく役割名で引く

意図と根拠: 色名や hex 値でスタイルを指定すると、テーマ切替で破綻する。
意味を持つ役割名でトークン化し、配色を切り替え可能にする。

- 良い例: CSS 変数 `--color-accent` や `--ed-surface` で指定する。
- 悪い例: スタイルシートに `#165e83` などの固定値を直接記述する。
- 例外: パレットの基礎となる元データを定義する定義体。
- 実験: [catalog-editorial/rationale/topic-first.md](../../experiments/catalog-editorial/rationale/topic-first.md)
- 出典: [Design Tokens Community Group 仕様](https://design-tokens.github.io/community-group/format/)

### 余った色をそのまま残さない

意図と根拠: 画面で使われない色がパレットに残ると、選択に迷いが生じる。
実際に役割を持つ色のみに絞り込み、保守の負担を減らす。

- 良い例: 19 の役割に割り当てられた必要な色のみを定義する。
- 悪い例: 生成ツールが作った無関係な濃淡スケールを全件保持する。
- 例外: 画面に出さない参照用の定義体。配色の元にした伝統色の一覧など。
- 実験: [color-schemes](../../experiments/color-schemes/README.md)

### 画面に組むより先に色だけの見本で判断する

意図と根拠: 複雑な UI に適用してからでは、造形と色の影響が混ざり合う。
色面を並べた標本を用意し、色単体の調和を先に検証する。

- 良い例: パレットカードや色帯を並べ、相性と明度差を先に確認する。
- 悪い例: 完成した画面にいきなり色を当てて全体の可否を議論する。
- 例外: 微小な文字サイズにおける個別の視認性確認。
- 実験: [catalog-editorial/README.md](../../experiments/catalog-editorial/README.md)

### 面は無彩色を基準にし、固有色は操作と状態に限る

意図と根拠: 面に強い色を使うと、コンテンツや文字の視認性が落ちる。
地と面を無彩色で静かに組み、有彩色は操作と強調に集中させる。

- 良い例: 背景を無彩色の白鼠や墨色にし、ボタンのみにアクセント色を使う。
- 悪い例: カードの面やヘッダー全体を有彩色で塗りつぶす。
- 例外: ブランドの告知など、強い情緒表現を意図する案内面。
- 実験: [catalog-editorial/rationale/topic-first.md](../../experiments/catalog-editorial/rationale/topic-first.md)

### 見本帳は固有のブランド色を持たない

意図と根拠: 見本帳自身が固有の色を持つと、展示する配色の見え方を歪める。
ホストは選択された配色をそのまま着る構造にする。

- 良い例: カタログの面の色を正本の配色定義から直接導く。
- 悪い例: カタログ固有のアクセントカラーをヘッダー等に残す。
- 例外: 成果物の表示と完全に独立したシステム管理バー。
- 実験: [docs/decisions/2026-09-19-catalog-host.md](../../docs/decisions/2026-09-19-catalog-host.md)

### 意味色は配色をまたいで意図を揃える

意図と根拠: 成功やエラーの意味色が配色ごとに変わると、状態を誤読する。
すべての配色で意味色の規則を一貫させ、認知の安定を図る。

- 良い例: 全配色でエラーに赤系、成功に緑系の色を割り当てる。
- 悪い例: 配色ごとにエラーの色を紫や青に勝手に変える。
- 例外: OS 標準のセマンティックカラーに委ねる場合。
- 実験: [color-schemes](../../experiments/color-schemes/README.md)

### コントラスト比は計算して確かめる

意図と根拠: 人間の目は周囲の明度によってコントラストを誤認しやすい。
相対輝度からコントラスト比を計算し、数学的に担保する。
満たすべき比の値はアクセシビリティのガイドラインが定める。本稿は確かめ方を扱う。

- 良い例: 計算ツールを用いて 4.5:1 や 3:1 の達成を数値で確認する。
- 悪い例: 画面を目視して「読めそうだから問題ない」と判断する。
- 例外: 写真やグラデーションなどの連続階調の上に重なる文字。
- 実験: [catalog-editorial/shared/contrast.ts](../../experiments/catalog-editorial/shared/contrast.ts)
- 出典: [WCAG 2.2 達成基準 1.4.3](https://www.w3.org/WAI/WCAG22/quickref/#contrast-minimum)

## 確認項目

- [ ] スタイル指定に固定のカラーコードが直接書かれていないか。
- [ ] 背景やカード面が無彩色を基調としているか。
- [ ] 意味色が全テーマで一貫した意図を持っているか。
- [ ] 本文と背景のコントラスト比が 4.5:1 を上回っているか。
- [ ] 画面で役割を持たない色がパレットに残っていないか。
