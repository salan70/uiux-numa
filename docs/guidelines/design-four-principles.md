## 目的

UI の可読性と操作性を保ち、情報の所属、重要度、役割を視覚的に伝える。
情報の構造と順序は [Information Architecture](information-architecture.md)、文言は [UX Writing](ux-writing.md) が扱う。
近接、整列、反復、対比は手段であり、白黒や角丸など特定の作風を全製品に強制しない。

## コア

### 読み取りと操作を成立させる

見た目を揃えるために、文字、操作の手がかり、内容を削らない。

### 見た目を意味に対応させる

所属と重要度を距離、配置、強さで表す。
意図してずらすなら、そのずれが示す関係を明確にする。

### 同じ役割の表現を繰り返す

役割や内容が違うものまで同じ形に押し込むより、意味に合う違いを保つ。

### 全体の規則を保って細部を整える

余白、文字、線、形に共通の規則を使う。
機械的な数値一致より、実寸での整い方と意図した印象を優先する。

上の順序は本稿内の判断にだけ使い、他のガイドラインとの優先順位へ広げない。

## Tips

### 文字の役割に既存のスタイルを割り当てる

意図と根拠: 採用済みの token の個数から画面内の階層数を制限しない。行長や文字サイズの値は Typography tokens が正本である。

- 適用: foundation
- コア: 同じ役割の表現を繰り返す
- コア: 全体の規則を保って細部を整える
- 良い例: heading と body を役割で使い分け、同じ役割では書体、太さ、行間を揃える。
- 悪い例: 各カードの収まりだけを理由に、同じ説明文を 13px、14px、15px と変える。
- 例外: 採用済みの組で役割を表せない場合は、不足と利用例を記録して追加を検討する。
- 実験: [Typography tokens](../../tokens/typography/README.md)

### 独自の造形は実寸で見かけを合わせる

意図と根拠: 外接矩形が同じだけでは揃って見えず、万能な補正値も無い。

- 適用: module
- コア: 全体の規則を保って細部を整える
- 良い例: 再生三角形と円形記号を同じ操作枠に置き、描画部分だけを実寸で調整する。
- 悪い例: 同じ bounding box に収めただけで揃ったと判断する。見かけを合わせるため操作領域を小さくする。
- 例外: ブランド指定や配布素材の改変制約は配置側で調整する。データ量を表す形は意味を変えない。
- 実験: [SVG 制作 Skill](../../skills/crafting-svg/SKILL.md)
- 出典: [Carbon: Pictograms — Alignment](https://carbondesignsystem.com/elements/pictograms/usage/#alignment)
