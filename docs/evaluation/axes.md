# 評価軸の定義

[評価の方針](policy.md)に挙げた 17 の軸について、定義、判定の目安、主に判定する観点を定める。
Experiment ごとに使う軸と重みを選ぶ手順は [review.md](review.md) に置く。

## 判定の共通ルール

- 判定は課題あり、許容、良いの 3 段階にする。
- 判定には根拠となる観察を必ず書く。該当箇所（ファイル、行、preview 名）を含める。
- 根拠が足りないときは保留とし、何があれば判定できるかを書く。
- 目安に照らして判定する。variant 間の違いは根拠に書き、順位を付けない。
- 目安は初期値であり、Experiment の目的に応じて補足してよい。補足は evaluation.md に書く。

## visual hierarchy

- 定義: 視線の順序が画面の目的と一致しているか。大きさ、余白、色、配置で重要度が伝わるか。
- 課題あり: 最初に見るべき要素が分からない。装飾が主要素と競合する。
- 許容: 主要素は分かるが、次に見る要素の順序が曖昧である。
- 良い: 目的、主要素、補助情報の順に自然に視線が移る。
- 主な観点: designer

## information density

- 定義: 画面あたりの情報量が利用者の目的と文脈に合っているか。
- 課題あり: 必要な情報が埋もれる。または不要な情報が多く、探す負担が大きい。
- 許容: 情報量は妥当だが、グループ化や余白に改善余地がある。
- 良い: 必要な情報だけが、判断に必要な単位でまとまっている。
- 主な観点: designer、UX / product

## discoverability

- 定義: 利用者が次に取れる操作と、その結果を予測できるか。
- 課題あり: 主要な操作が隠れている。または操作できることが分からない。
- 許容: 主要な操作は見つかるが、補助的な操作は説明がないと分からない。
- 良い: 主要な操作も補助的な操作も、探さずに見つかる。
- 主な観点: UX / product、interaction / motion

## information architecture

- 定義: 情報の分類、順序、階層が利用者の心理モデルと合っているか。
- 課題あり: 関連する情報が離れている。または順序が作業の流れと合わない。
- 許容: 構造は妥当だが、ラベルや区切りで補足が必要である。
- 良い: 分類と順序が作業の流れに沿い、説明なしで理解できる。
- 主な観点: UX / product

## interaction clarity

- 定義: 操作の対象、方法、結果が明確か。有効、無効、進行中などの状態が分かるか。
- 課題あり: 何をすれば進むか分からない。または操作の結果が予測できない。
- 許容: 主な操作は明確だが、状態の変化に気づきにくい箇所がある。
- 良い: 操作の対象、方法、結果、状態が常に明確である。
- 主な観点: interaction / motion

## writing clarity

- 定義: 文言が短く具体的で、利用者の言葉で書かれているか。次の行動が分かるか。
- 課題あり: 意味が曖昧である。専門用語が多い、または責める調子である。
- 許容: 意味は通じるが、冗長または行動につながらない箇所がある。
- 良い: 一読で意味と次の行動が分かり、調子が一貫している。
- 主な観点: UX writing

## motion appropriateness

- 定義: 動きが状態の変化や空間関係の理解を助けているか。速度と量が適切か。
- 課題あり: 動きが理解を妨げる、または遅い。reduced motion に対応していない。
- 許容: 動きは妨げにならないが、理解を助けてもいない。
- 良い: 動きが変化の因果を伝え、reduced motion でも意味が保たれる。
- 主な観点: interaction / motion

## feedback quality

- 定義: 操作の結果、成功、失敗、進行中が適切なタイミングと手段で伝わるか。
- 課題あり: 結果が伝わらない。または遅すぎる、多すぎる。
- 許容: 結果は伝わるが、タイミングや手段に改善余地がある。
- 良い: 必要な結果だけが、適切なタイミングと手段で伝わる。
- 主な観点: interaction / motion、UX writing

## consistency

- 定義: 同じ意味に同じ表現を使い、画面内と既存のプロダクトで一貫しているか。
- 課題あり: 同じ操作や状態に異なる表現が混在する。
- 許容: 主要な要素は一貫しているが、細部に揺れがある。
- 良い: 表現、配置、文言、動きが画面内で一貫している。
- 主な観点: designer、platform

## accessibility

- 定義: キーボード、支援技術、拡大表示、色覚多様性で利用できるか。WCAG の達成基準に照らす。
- 課題あり: キーボードで操作できない。支援技術に状態が伝わらない。コントラストが不足する。
- 許容: 主要な操作は利用できるが、補助的な情報の伝達に不足がある。
- 良い: すべての操作と状態がキーボードと支援技術で利用でき、視覚条件に依存しない。
- 主な観点: accessibility

## platform fit

- 定義: 対象プラットフォームの慣習、標準部品、入力手段に合っているか。
- 課題あり: 標準の操作や部品と異なる振る舞いをし、利用者の期待を裏切る。
- 許容: 慣習に沿うが、標準部品で代替できる独自実装がある。
- 良い: 慣習と標準部品を活かし、そのプラットフォームらしく振る舞う。
- 主な観点: platform

## delight

- 定義: 目的の達成を妨げずに、心地よさや驚きを与えているか。
- 課題あり: 演出が目的の達成を妨げる。または不快である。
- 許容: 妨げにはならないが、印象に残る要素がない。
- 良い: 目的の達成を助ける形で、心地よさが設計されている。
- 主な観点: designer、interaction / motion

## perceived performance

- 定義: 待ち時間が短く感じられるか。応答が即時に返り、進行が伝わるか。
- 課題あり: 操作後に無反応の時間がある。または待ち時間の見通しがない。
- 許容: 応答はあるが、待ち時間の見通しや先読みが弱い。
- 良い: 即時の応答、進行の表示、optimistic UI などで待ちを感じにくい。
- 主な観点: interaction / motion、implementation

## localization robustness

- 定義: 文言の長さ、語順、日付や数値の形式が変わっても崩れないか。
- 課題あり: 文言を長くすると崩れる。または文の連結に語順を仮定している。
- 許容: 主要な文言は耐えるが、固定幅や連結に依存する箇所がある。
- 良い: 文言の長さや形式が変わってもレイアウトと意味が保たれる。
- 主な観点: UX writing、implementation

## implementation cost

- 定義: 実装と検証に必要な工数、依存、変更範囲がどの程度か。
- 課題あり: 効果に対して工数や依存が大きい。または変更範囲が広い。
- 許容: 工数は妥当だが、依存や特殊な実装がある。
- 良い: 標準的な実装で済み、依存と変更範囲が小さい。
- 主な観点: implementation

## maintainability

- 定義: 構造が読みやすく、変更や再利用がしやすいか。
- 課題あり: 状態や責務が絡み合い、変更の影響範囲が読めない。
- 許容: 構造は追えるが、重複や暗黙の依存がある。
- 良い: 責務が分かれ、テストと再利用がしやすい。
- 主な観点: implementation

## brand fit

- 定義: 見た目、文言、動きの調子がプロダクトの人格と合っているか。
- 課題あり: プロダクトの調子と明らかに異なる表現がある。
- 許容: 大きな違和感はないが、独自性が弱い。
- 良い: 表現の調子がプロダクトの人格を強めている。
- 主な観点: designer
