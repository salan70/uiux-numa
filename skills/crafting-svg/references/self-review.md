# 自己確認

「洗練された」を、比較できる観察に置き換える。
手順 4（比較と改善）で、描画した画像を読んで確認する。
見た目の改善と、意味の理解や識別などの UX 上の改善は分けて記録する。
ここでの判定は制作者の自己確認であり、採用の判断には使わない。採用は多観点の評価と人間の判断による。

## 確認の入力

- 比較シート（`just svg-sheet`）: 実利用サイズを含む複数サイズ、明暗の背景、最小サイズの 4 倍拡大
- 利用画面の撮影（`just web-shot`）: 周囲の文字、面、余白と一緒に見る
- 既存の基準（あれば）: 既存のアイコン集や現行の asset を同じシートに並べる

## 見た目の観察（造形）

各項目に「観察したこと」と「該当する asset とサイズ」を書く。判定は 良い / 許容 / 課題あり の 3 段階。

| 項目           | 観察の仕方                                                                          | 参照                  |
| -------------- | ----------------------------------------------------------------------------------- | --------------------- |
| 見かけの大きさ | 組の中で 1 つだけ大きく、または小さく見えないか。円は正方形より小さく見えていないか | `ICON-06`、`FORM-02`  |
| 線幅と重さ     | 組の中で 1 つだけ太く、または細く見えないか。水平線が重く見えないか                 | `FORM-03`、`FORM-06`  |
| 端点と角       | cap と join が組の中で統一されているか。鋭角が切れていないか                        | `ICON-07`、`SVG-02`   |
| 視覚的な中心   | 幾何学的な中心ではなく、見た目で中央に置かれているか                                | `FORM-01`             |
| 細部の量       | 最小サイズで判別できない要素がないか。隙間が潰れていないか                          | `FORM-04`、`ICON-08`  |
| ピクセルの整列 | 4 倍拡大で線がぼやけていないか                                                      | `ICON-09`、`SVG-01`   |
| 曲線の質       | 接続点が折れて見えないか。円弧の連続が滑らかか                                      | `FORM-11`             |
| 単色での成立   | 明暗どちらの背景でも形が読めるか                                                    | `FORM-08`、`UIFIT-07` |
| 既製感         | 有名なアイコン集の形をそのままなぞっていないか。固有の要素が 1 つあるか             | `LOGO-04`、`FORM-04`  |

## UX 上の観察（意味と適合）

| 項目         | 観察の仕方                                                           | 参照                   |
| ------------ | -------------------------------------------------------------------- | ---------------------- |
| 意味の伝達   | ラベルを隠して、意味を推測できるか。比喩が既知の対応か               | `ICON-02`              |
| 識別         | 組の中で互いに取り違えないか。16px で見分けられるか                  | `ICON-03`、`ICON-11`   |
| 主従関係     | 利用画面で、アイコンが文字より目立っていないか                       | `UIFIT-08`、`UIFIT-09` |
| 周囲との調和 | 線幅、角丸、余白が周囲の文字と面に合っているか                       | `UIFIT-10`             |
| コントラスト | 意味を担う図形が隣接色に 3:1 以上か                                  | `UIFIT-02`             |
| 名前と役割   | `role="img"` と `<title>`、または `aria-hidden` が用途に合っているか | `UIFIT-04`、`UIFIT-05` |

意味の伝達と識別は、制作者の自己確認では確かめきれない。
Brief を知らない別の agent か人にラベルなしのシートを見せた結果は、ユーザーテストではないため仮説として記録する。

## 記録の形式

反復ごとに次を残す。README の Variants の反復の記録の表に写す。

```text
round N
- 観察: <項目>: <観察したこと>（<asset>、<サイズ>、<シート名>）
- 変更: <part-id> の <何を> <どう>
- 参照: <知識 ID>
- 終了理由: 指摘なし | 上限到達 | 画像を読めない
```

## 終了条件

- 見た目と UX の両方で「課題あり」が残っていなければ終了する。「許容」は理由を書いて残してよい。
- 反復は 1 variant あたり 3 回まで。上限に達したら、未解決の項目を報告する。
- 画像を読めない場合は、その項目を未検証として報告する。推測で判定しない。
- 見た目の改善のために要素を足さない。既にある形を減らして整えられないかを先に問う（`SKILL-02`）。
