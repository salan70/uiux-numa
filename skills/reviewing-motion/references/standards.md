# 動きの点検用の出発値

上流 `STANDARDS.md` を写し、必須と仮説を分けた。
引用するときは「出発値」と書く。Brief の頻度と実操作を優先する。

## 動かすか（仮説）

| 頻度の目安    | 出発点                 |
| ------------- | ---------------------- |
| 1 日 100 回超 | 動かさない案を先に試す |
| 1 日数十回    | 減らすか無くす         |
| たまに        | 標準                   |
| 初めて / 稀   | 喜びを足してよい       |

キーボード起点でも、頻度を確認する。
登録完了は稀な操作として扱う。

目的の語彙はフィードバック、空間の連続、状態の明示、急な変化の緩和、説明、喜びである。

## 曲線（仮説）

- 入退場: `ease-out`
- 画面上の移動: `ease-in-out`
- hover / 色: `ease`
- 無限の進行: `linear`

```css
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);
```

既存 token があればそれを使う。

## 時間（仮説）

| 要素               | 時間         |
| ------------------ | ------------ |
| ボタン押下         | 100–160ms    |
| 小さな面           | 125–200ms    |
| ドロップダウン     | 150–250ms    |
| モーダル、ドロワー | 200–500ms    |
| 説明               | 長くしてよい |

300ms 超は理由を求める。理由があれば残してよい。

## 物理（仮説）

- `scale(0)` で始めない。`scale(0.9–0.97)` と透明度
- トリガー付きの面は原点をトリガー側。中央モーダルは中央
- 押下の `scale(0.97)` は 160ms 前後

## 中断（観察で判定）

連続発火は transition を優先する。
keyframes は先頭へ戻る。実操作でチラつきが出たら指摘する。

## 性能（計測が必要）

`transform` と `opacity` 以外は layout と paint を伴いやすい。
クリック取りこぼしは、高さ変化の実操作で確認する。
フレーム落ちは計測なしで断定しない。

## アクセシビリティ（要件）

```css
@media (prefers-reduced-motion: reduce) {
  .element {
    animation: fade 0.2s ease;
  }
}

@media (hover: hover) and (pointer: fine) {
  .element:hover {
    transform: scale(1.05);
  }
}
```

減らす設定はゼロではない。理解を助ける変化は残す。
キーボード操作そのものは要件として必ず通す。動きの有無は仮説である。

## 感触が決まらないとき

時間を 2〜5 倍にする。
DevTools のアニメーションパネルでコマ送りする。
ジェスチャは実機を優先する。
翌日の目で見直す。
