## Problem

サイト名「UI/UX NUMA」は、サイドバー題字とホーム大見出しで LINE Seed JP の文字列のまま組まれている。
マークは `nu-dot`（字画 4、round cap、半円、赤い点）に決まったが、隣の文字列は書体の字形で、マークと作図の規則が揃っていない。
利用者は 2026-09-25 に、タイトル自体のロゴを、マークとテイストを合わせて作ることを求めた。
同時に、動きの有る版と無い版を両方持ち、点はどの版でも残すことを求めた。

## Target

Catalog を見る利用者を対象にする。
最も頻度が高い面はサイドバー題字（高さ 20px 相当）、最も大きい面はホーム大見出し（42〜96px）である。

## Scope / Domains

対象は wordmark 1 個と、マークとの lockup（横組み）である。
domain は `logo-brand-identity`、`visual-design`、`accessibility`。
`animation-motion` は入れない。`logo-brand-identity` に topic が無いため、2 番目以降の domain が topic を決め、Motion 画面に載ってしまう。
Catalog には載せない（[掲載しない Experiment の ADR](../../docs/decisions/2026-09-22-unlisted-experiments.md)）。

variant で変える軸は、字の大小（小文字 / 大文字）と、赤い点の置き場所（i の点 / 句点）の組である。
字画、端点、格子、baseline、字間、動きの曲線と時間は 2 案で共通にする。

比喩と印象は利用者が決めた。マークとテイストを合わせることである（crafting-svg の手順 1）。

## Constraints

- `<text>` を使わず path で作図する。フォントの outline 化は [SVG ツールチェーンの ADR](../../docs/decisions/2026-09-18-svg-toolchain.md) で却下済みである。
- 色は `currentColor` と、利用画面の CSS が与える `part-wordmark-dot` だけにする。
- 字ごとに `part-wordmark-<字>` の id を付ける。preset-default の mergePaths が同じ属性の path を 1 本にまとめ、字ごとに線を引く動きができなくなるためである。
- マークと同じ高さ 32 の座標で描き、baseline を y 28 に揃える。lockup は高さを 1 つ与えれば並ぶ。
- 点はどの版でも描く。動きの無い版は点が据わった姿で、動きの有る版は点が最後に落ちて据わる。
- 動きはマークの Catalog 実装（`apps/catalog/src/catalog.css` の `logo-mark--enter`）と同じ曲線、時間、落とし方にする。
- `prefers-reduced-motion: reduce` では線を引かず、点を落とさず、透明度の変化だけを残す。

## Hypothesis

マークと同じ字画 4、round cap、半円で wordmark を作図すると、マークと文字列が 1 つの規則から出た形に見える。
赤い点を wordmark にも 1 つ置くと、マークの点と呼応して 2 つが 1 組に見える。
点の置き場所が、組の読み方（字の一部か、文の終わりか）を決める。

## Variants

| id            | 仮説                                                                                                                                                                                                                                    | 変えた軸                 | 実装                    |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | ----------------------- |
| `caps-period` | 大文字で組み、句点を赤い点にすると、マークの点（左上）と句点（右下）が組の両端を押さえ、1 つの文になる。字幅をマークの 2:3 と黒の密度で、角をマークと同じ円弧の接線で、字間を白の面積で決めると、縦長やカクカクに見えず均等な濃さになる | 大文字、点は句点（右下） | `variants/caps-period/` |

### 削除した variant

2026-09-25 に利用者が `caps-period` を採用した。`lower-tittle` はコードを削除し、仮説と軸だけを残す。

- `lower-tittle`: マークの n と同じ x-height の小文字で組み、i の点を赤くすると、マークの nu が字の続きとして読める。変えた軸は小文字、点は i の点。

### 造形のパラメータ

2 案で共通の値である。

| 項目     | 値                       | 理由                                                                  |
| -------- | ------------------------ | --------------------------------------------------------------------- |
| 高さ     | 32                       | マークの viewBox と同じ。lockup で高さを 1 つ与えれば baseline が揃う |
| baseline | y 28（中心線）           | マークの n の足と同じ                                                 |
| 字画     | 4、round cap、round join | マークと同じ。斜画の角も丸め、マークの曲線に寄せる                    |
| 点       | 半径 2.5                 | マークの点と同じ大きさ                                                |

字間と語間は案ごとに違った。
削除した `lower-tittle` は中心線の間隔 8（外縁の隙間 4）と語間 20 の固定値だった。
`caps-period` は round 2 で、白の面積から字ごとに決める方式に替えた（下の座標の導出）。

`caps-period`（round 4）

利用者は 2026-09-25 に、点を句点にする案を選び、字が縦長でいまいちと判断した（round 2 で直した）。
続けて、M だけ横幅が突出して広いことと、マークの滑らかな曲線に比べてカクカクした印象を指摘した（round 3 で直した）。
round 3 の N と M のうねりが気になると指摘した（round 4 で直した）。
式は crafting-svg の優先順（最小サイズの可読性、作図の決定性、比例の美学）で選んだ。
黄金比は、値を目分量で置かないための決め方として使い、品質の根拠にはしない（`LOGO-10`）。
見た目を良くした条件（最も狭い隙間、句点の寄せ、M の V の白、斜画のずれの上限）は、16px と 120px の描画を見て足したもので、式からは出ていない。

### 動き

動きの有る版は、マーク、wordmark、点の順に線を引いて落とす。

| 対象          | 開始                            | 時間  | 曲線                             |
| ------------- | ------------------------------- | ----- | -------------------------------- |
| マークの線    | 0ms                             | 800ms | `cubic-bezier(0.65, 0, 0.35, 1)` |
| wordmark の字 | 150ms から 1 字 60ms ずつ       | 500ms | 同上                             |
| マークの点    | 570ms                           | 380ms | 落下は inQuad、潰れて戻る        |
| wordmark の点 | 点を持つ字を引き終える 230ms 前 | 380ms | 同上                             |

wordmark の字は 500ms で、マークの 800ms より短くする。字が 9 つあり、800ms では最後の字が 1.4 秒まで残る。

## Evaluation

比較評価は行っていない。
配布用 SVG の検査、120px の描画、モックの完成状態と動きの途中の撮影で確かめた。
未確認の軸は、10 配色 × light / dark での点の見え方、サイドバーの 20px での可読性の実機確認、Safari と Firefox での動きである。

## Decision

- 採用: `caps-period`（round 4）
- 判断者: 利用者
- 判断日: 2026-09-25
- 理由: 利用者は、点を句点にする考えを好み、round 2〜4 で縦長、M の幅、カクカク、うねりを指摘した。round 4 を見て「それで行きます」と判断した。

2026-09-25 に Catalog へ適用した。

| 面             | 実装                                                               | 動き                                             |
| -------------- | ------------------------------------------------------------------ | ------------------------------------------------ |
| サイドバー題字 | `LogoMark` + `Wordmark`（`apps/catalog/src/components/icons.tsx`） | なし。全画面に常に出るので、数十回見ることになる |
| ホーム大見出し | `LogoMark animated` + `Wordmark animated`                          | マークと字を引き、句点を落とす                   |

名前は見えない文字列（`logo-label`）が担い、SVG は `aria-hidden` にする。
ホーム大見出しの lockup の高さは、display の大きさと、版面の幅の 1/8.3 の小さいほうにする。lockup の幅は高さの約 8.2 倍で、390px の画面でも溢れない。
Catalog は `pathLength="1"` で破線を 0..1 に揃え、モックのように長さを測る JS を持たない。

## Rejected reasons

- `lower-tittle`: 利用者は、点を句点にする考えのほうが好きだと判断した（2026-09-25、判断者は利用者）。制作中の観察では、マークの点と i の点が同じ高さで並んで競っていた。コードは Decision まで残す。
