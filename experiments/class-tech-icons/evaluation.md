- Experiment: [README](README.md)

- 観点: designer、UX / product、accessibility、implementation
- 手順: [docs/evaluation/review.md](../../docs/evaluation/review.md)

### 軸の定義の補足

`discoverability` の目安は操作の発見を想定している。
この Experiment では静的な資料の目印なので、次のように読み替える。

- 課題あり: ラベルと並べても、そのアイコンが指す話題が分からない。別の話題と取り違える。
- 許容: ラベルと並べれば分かるが、アイコン単独では推測できない。
- 良い: ラベルと並べたとき理解を助け、アイコン単独でも話題を推測できる。

`brand fit` の「プロダクトの人格」は、授業資料サイトの調子とする。
学生向けで、堅すぎず、既製のアイコン集をそのまま貼ったようには見えないこと。

## 観点別の要点

### designer

- `line-round` は 3 軸とも良い。24px の外形の散りが最小で、96px の章扉では見出しの 1.31 倍と主役になる。
- `solid` は 96px の投影で最も強い（見出しの 1.95 倍）が、20px と 24px では文字と競合する。投影と手元で逆の評価になる。
- `duotone` の accent は、同じ役割に対して 7 種類の形と 4.1 倍の面積差があり、組の規則として成立していない。
- 記録: [evaluation/designer.md](evaluation/designer.md)

### UX / product

- `api` は 4 案とも「API」に届かず、往復矢印から出るのは「交換」「同期」「送受信」まで。`test` も 4 案とも「実験」か「完了」が先に出る。描き方ではなく比喩で決まるという仮説は、この範囲では支持された。
- 利用画面のモックで、見出しの前のアイコンが見出し語と一致していない。`solid` ではこれが実害になり、「演習」とチェック済みの検査票が「演習は提出済み」と逆の意味に読めた。
- 比較グリッドは列見出しに asset の id を印字しており、ラベルなしの読み取りには使えない。代わりに名前を伏せた別の描画で読み取った。
- 記録: [evaluation/ux-product.md](evaluation/ux-product.md)

### accessibility

- 利用画面の 4 場面すべてで、4 案とも非テキストのコントラスト 3:1 を満たす。
- `duotone` の `fill="#ce1126"` は直書きのため、暗背景（2.93:1）と forced-colors でテーマに追従しない。README が挙げた `#part-*-accent` の上書き口は、モックに実装されていない。
- `duotone` の accent は色だけで意味を担っておらず、単色化しても 8 個とも意味が残る（1.4.1 を満たす）。ただし 8 個中 4 個で accent が線に重なり、その境界はサイドバーで 1.00:1 になる。
- モックはアイコンの大きさを px で固定しており、文字だけを拡大する設定でアイコンが取り残される。
- 記録: [evaluation/accessibility.md](evaluation/accessibility.md)

### implementation

- 4 案 × 8 個の全 32 ファイルで `just svg-optimize` を再実行し、配布用と 1 バイト単位で一致した。source と dist のずれはない。
- source と dist を 16 倍で描画して画素を比較し、32 ファイルすべて一致した。SVGO が落とす属性は現時点で描画に影響しない。
- `Mock.tsx` は同じアイコンを 1 文書に 2 回 inline 展開するため、`part-*` の id が重複する。CSS の上書きは効くが HTML としては不正である。
- `duotone` は「`line-round` に accent を足しただけ」ではなく、比喩と座標も違う。accent の有無だけを取り出すには、`line-round` を複製して accent を足した版が別に要る。
- 記録: [evaluation/implementation.md](evaluation/implementation.md)

## 人間の判断待ちの論点

- `api` と `test` の比喩は 4 案とも意味に届いていない。比喩を選び直すか、ラベル併記を前提として許容するか。
- `duotone` を使う場合、暗いテーマと forced-colors で accent をどう扱うか。利用画面の CSS で `#part-*-accent` を上書きする実装を入れるか、accent を `currentColor` に戻すか。
- `solid` は投影で最も強く、手元では最も重い。章扉だけ `solid`、本文は線画、のように用途で使い分けるか。
- 配布用の `role="img"` と `<title>` を残すか。装飾として `aria-hidden` で置く利用画面では、`<title>` が hover の吹き出しとして重複する。
- `part-*` の id が 1 文書で重複する点を許容するか、接頭辞や `<symbol>` に変えるか。
- 実際の授業資料サイトが赤（accent）を何に使っているかは未確認である。`duotone` の赤が既存の役割と衝突しないかは、実物を見て判断する必要がある。
- 学生への実地確認は行っていない。意味の読み取りは agent による推測であり、ユーザーテストではない。
