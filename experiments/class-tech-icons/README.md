## Problem

授業資料サイト（`class_document`、VitePress で公開）とそのスライド（Marp）では、話題の目印に絵文字を使っている。
技術の話題（ターミナル、コード、Git、データベース、API、テスト、AI、Web）を示す汎用的なアイコンの組がなく、ページとスライドで表現が揃わない。
利用者が渡したテーマ「資料で使える技術に関する汎用的なアイコン」に沿って、描き方だけを変えた複数案を作り、利用者が判断する。

この Experiment は、利用者がテーマを渡し AI が複数案を作る進め方の最初の適用である。
`hako-feature-icons` では AI が方向を定義して選ばせたが、利用者は「自分が渡したテーマに沿った複数案から判断したい」と求めた。

## Target

- 教員（利用者）: 授業資料とスライドを Markdown で書く。トップページの項目、見出し、スライドの章扉と箇条書きに同じアイコンを使いたい。
- 学生: PC とスマートフォンでページを読み、教室で投影されたスライドを見る。

## Scope / Domains

対象領域は iconography、visual design、consistency、accessibility。
テーマは全 variant で共通にし、variant で変える軸は描き方だけにする。

- 線か塗りか、線幅、端点と角
- 単色か、accent の 2 色か

アイコンの意味と個数（8 個）、viewBox、利用画面のモックは全 variant で共通にする。

対象のアイコンと意味は次のとおり。

| id         | 意味                                 |
| ---------- | ------------------------------------ |
| `terminal` | ターミナル、コマンドライン、シェル   |
| `code`     | ソースコード、エディタ、実装         |
| `branch`   | バージョン管理、Git のブランチと履歴 |
| `database` | データベース、保存、SQL              |
| `api`      | API と通信、リクエストとレスポンス   |
| `test`     | テスト、検証、合格と不合格           |
| `ai`       | AI と LLM、生成、モデル              |
| `web`      | ブラウザと Web、画面、フロントエンド |

## Constraints

- viewBox は `0 0 24 24`。自己完結した静的 SVG にする。`text` を使わない。`just svg-check --viewbox "0 0 24 24"` を通す。単色の variant は `--mono` も通す。
- 利用画面は 2 つ。VitePress 風のページ（サイドバーの項目 20px、見出しの前 24px、文字色）と、Marp 風のスライド（章扉 96px、箇条書き 32px、primary #002d62 と accent #ce1126）。
- 8 個で見かけの大きさと線の太さを揃える。20px でも互いに取り違えない。
- 編集用の原本を `variants/<id>/source/<icon>.svg`、配布用を `variants/<id>/dist/<icon>.svg` に置く。`index.tsx` は配布用を `?raw` で inline に展開する。
- 部分編集の単位に `part-<icon>-<role>` の id を付ける。2 色の variant は accent の要素に `part-<icon>-accent` を付ける。
- モック（`Mock.tsx`、`mock.css`）は全 variant で同一にし、`diff` で確認する。追加の npm 依存を入れない。

利用者が渡したテーマは次のとおり（原文）。

```text
/Users/tetsuooda/Projects/Class_Projects/class_document
の資料で使える技術に関する汎用的なアイコン。
```

## Hypothesis

同じテーマと同じ 8 個の意味でも、描き方（線か塗りか、端点、色数）で資料の印象が変わり、利用者はその差で判断できる。
文字と並ぶ 20px と 24px では線画が文字の太さに馴染み、投影される 96px では塗りや 2 色が遠くから識別しやすい。
8 個の中で「AI」と「API」は既知の比喩が弱く、描き方より比喩の選び方で識別が決まる。

## Variants

テーマは全 variant で共通にし、描き方だけを変える。
比喩は描き方に合わせて選び直してよい。変えた場合は理由を残す。

| id            | 仮説                                                                                                     | 変えた軸                               | 実装                    |
| ------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------- | ----------------------- |
| `line-round`  | 端点と角を丸くした線画なら、文字と並ぶ 20px で本文に馴染み、学生向け資料の堅さを線の丸さだけで緩められる | 端点と角 = round、線が主、単色         | `variants/line-round/`  |
| `line-square` | 未定                                                                                                     | 端点と角 = butt と miter、線が主、単色 | `variants/line-square/` |
| `solid`       | 未定                                                                                                     | 塗りと負の空間、単色                   | `variants/solid/`       |
| `duotone`     | 未定                                                                                                     | 線 + accent の塗り 1 か所、2 色        | `variants/duotone/`     |

### 制作条件

4 案とも、描き方のパラメータ（線幅、端点と角、塗りか線か、色数）を担当者が指定し、Skill `crafting-svg` を読み込んだ subagent に 1 variant ずつ任せた。
テーマ、8 個の意味、利用画面のモックは共通。反復は最大 3 回。利用画面の撮影まで subagent が行い、README への記録は担当者が写した。

### 描き方ごとの記録

### line-round

描き方: 線幅 2、`round` の端点と角、線が主で塗りは 1 か所、単色。

- 座標は整数（線幅 2 は偶数のため）。keyline は円 20、正方形 18、横長 20×16 で見かけの大きさを揃えた（ICON-06、SVG-01）。
- 塗りは `ai` の小さい火花だけ。半径 3 の星を線で描くと 20px で塊になるためである（ICON-10）。
- 比喩: `terminal` は角丸の窓とプロンプトとカーソル、`code` は枠なしの山括弧にキャレット、`branch` は幹と 3 ノードの分岐、`database` は円柱、`test` は三角フラスコ、`web` は地球儀、`api` は往復矢印、`ai` はスパークル。
- 却下: `test` の checkbox（角丸正方形が `terminal` と衝突する）、`web` のブラウザ窓（同上）、`api` の波括弧（`code` と記号の系統が重なり 20px で丸括弧と紛れる）、`api` の接続口（接続を読み取れない）、`ai` の吹き出しと星（20px で星が `+` に潰れコメント追加に見える）、`ai` のチップ（脚が潰れ、意味が LLM でなくハードウェアに寄る）。

| round | 観察                                                                                                                     | 変更                                                                            | 参照                      | 終了理由 |
| ----- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- | ------------------------- | -------- |
| 1     | 8 個とも 20px で識別できる。`code` が高さ 12 で 1 つだけ小さい。`terminal` の内容が下に寄る。`test` の首が 20px で潰れる | `code` を 20×16 へ。`terminal` の内容を上下中央へ。`test` の首を内側 4 に広げた | ICON-06、FORM-01、ICON-08 | 指摘あり |
| 2     | 3 点とも解消し、組の見かけの大きさが揃った。`web` がシート上で最も濃い                                                   | なし（要素を足さずに据え置いた）                                                | ICON-06、SKILL-02         | 指摘あり |
| 3     | 利用画面では `web` の濃さは問題にならず、20px で本文より軽い                                                             | なし                                                                            | ICON-06                   | 指摘なし |

未解決: `branch` は 20px で細部が最も密で読み取りが遅い（許容とした）。`test`（フラスコ）と `api`（往復矢印）が Brief を知らない人に通じるかは未検証。96px 専用の版は作っていない（ICON-11）。

### line-square

描き方: 線幅 2、`butt` と `miter`、角丸なし、線が主で塗りは 1 か所、単色。

- 座標は整数、斜線は 45° のみ。鋭角は最も鋭いところで 90°（miter 比 1.41）なので、既定の miterlimit 4 に収まり角が落ちない（ICON-09、SVG-02）。
- 塗りは `ai` の火花だけ。20px で小さい輪郭は潰れるためである（ICON-10）。
- 比喩: `terminal` は窓枠とプロンプトとカーソル、`code` は波括弧、`branch` は幹と直角と 45° の肘と正方形のノード、`database` は面取りした樽と中段の継ぎ目、`api` は往復の矢印、`test` は 45° で広がるビーカー、`ai` は菱形と火花、`web` はブラウザの窓。
- 比喩を変えた 3 個の理由: `web` は地球儀が円と楕円の経線に依存し、角張った描き方では作れないためブラウザの窓にした。`code` は line-round の山括弧をなぞらず、波括弧なら 45° の切り込みで角張らせられるためである。`ai` は 4 点星の凹んだ曲線を 45° の直線に置き換えると菱形に退化するので、最初から菱形にした。
- 却下: `ai` のチップ（20px でピンと内側が潰れ、Material の memory をなぞる）、`ai` の火花を線にする案（20px で菱形が 2 個並んで見える）、`api` のプラグとソケット（20px で `[-0]` としか読めない）、`api` の矢印と終端の壁（壁が枠線に見える）。

| round | 観察                                                                                                       | 変更                                          | 参照                      | 終了理由 |
| ----- | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------- | ------------------------- | -------- |
| 1     | `ai` と `api` の候補を 3 個ずつ比較して選んだ。組では `database` が「壺」に見え、データベースと読めない    | なし（候補の選定のみ）                        | ICON-02、ICON-08          | 指摘あり |
| 2     | `database` の 3 案を比較した。高い面取りは鍋、薄い蓋だけは瓶に見え、中段の継ぎ目のある案だけが円盤に読めた | 上面を 2 の面取りに縮め、中段の継ぎ目を足した | ICON-02、FORM-04、ICON-08 | 指摘なし |
| 3     | `terminal` と `web` はどちらも同寸の枠だが、20px でも中身で取り違えない                                    | なし                                          | ICON-03                   | 指摘なし |

未解決: `code` の波括弧は、ブロック記号を持つ言語を知る人を前提にしている。`terminal` と `web` が同寸の枠を共有する点の第三者による識別は未検証。`ai` の菱形は「生成」より「宝石」に見える可能性が残る。SVGO は既定値の `butt` と `miter` を配布用から落とすが、値が既定と同じなので描画は変わらない。

### solid

描き方: 線なし、塗りのシルエットと負の空間、単色。

- 正の棒は太さ 4、負の空間（切り抜き）は幅 2 で 8 個統一。切り抜き 2 は 20px で 1.67px に落ちるが潰れない下限である（ICON-08）。正の棒 4 は 96px の投影で遠くから読ませるためである（ICON-05、FORM-03）。
- 外形の角丸 2、切り抜きの端点半径 1。棒の端点半径は太さの半分なので、規則が一致する（ICON-07）。
- 座標は整数か 0.5 刻み。45° の接合と円弧から生じる端数だけ小数 2 桁にした（ICON-09、SVG-01）。keyline は横長 20×14、円 r=9、縦長 14×18 で見かけの大きさを揃えた（ICON-06、FORM-02）。
- 比喩: `terminal` は窓の塗りにプロンプトとカーソルを抜く、`code` は山括弧 2 つ、`branch` は主線と右下へ分かれる枝と commit の円 3 つ、`database` は円柱に溝 2 本、`test` は検査票にチェックを抜く、`web` は地球儀、`api` は往復する 2 本の矢印、`ai` は大小 2 つのきらめき。
- 却下: `api` の波括弧と点（`code` の山括弧と括弧の組として取り違える）、`api` の差込口と差込（20px で塊になる）、`ai` のチップ（20px で歯車に見え設定と混同する）、`ai` の吹き出し（中のきらめきが潰れてコメントに見える）。

| round | 観察                                                                                | 変更                                                                     | 参照             | 終了理由 |
| ----- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ---------------- | -------- |
| 1     | 8 個とも 20px で識別できた。`branch` が小文字の h に見える。`test` の塗りが最も重い | なし（観察のみ）                                                         | ICON-02、FORM-03 | 指摘あり |
| 2     | 同上                                                                                | 分岐点を 1 上げて最初の commit の直下で分かれる形にした。`test` を縮めた | ICON-02、FORM-03 | 指摘あり |
| 3     | 利用画面の 20px で `test` だけ隣より小さく見えた                                    | `test` の幅だけ戻した                                                    | ICON-06          | 指摘なし |

未解決: 20px のサイドバーでは、塗りのアイコンが灰色のラベルよりやや密に見える（ICON-10 の観察）。開いた形（`code`、`api`、`ai`）と塊（`terminal`、`test`、`web`）の見かけの重さは完全には揃わず、塗りの語彙では原理的に残る差として許容した。`branch` は 20px で小文字の h に近い。`code` の山括弧は比喩そのものが既製と同じで固有性が低い。

### duotone

描き方: 線幅 2、`round` の端点と角、線が主で accent の塗りを 1 か所、2 色。

- 線幅と端点は `line-round` と揃え、比較の軸を「accent の有無」だけに絞った（UIFIT-10）。
- accent は各アイコンに 1 要素だけ置き、`fill="#ce1126"` を直書きして `part-<icon>-accent` の id を付けた。`var()` を使わず、利用画面の CSS から `#part-*-accent` で上書きできる（UIFIT-07、SVG-04）。
- accent の置き場所: `terminal` は入力位置のブロックカーソル、`code` は `</>` の斜線、`branch` は分岐点のノード、`database` は中の 1 レコード、`api` は戻りの矢じり、`test` は中の試料、`ai` は生成の火花、`web` は経線と赤道が交わる節。
- 比喩を変えた点: `test` は合格印（チェックボックスと赤チェック）も描いたが、赤の面積が組で突出し、`terminal` と同じ角丸長方形が 2 つ並ぶため却下した。`database` は赤の余白を確保するため中段の帯を外した。`web` はブラウザ窓案が 20px で `terminal` と同じ「赤を含む角丸長方形」になるため地球を維持した。
- 却下: `api` の 2 端点と中央のひし形（リンクに見え通信の向きが出ない）、`api` の境界を越える矢印（20px で線が 3 種に増え潰れる）、`ai` のチップ（ピンが潰れハードウェアに寄る）、`ai` の吹き出し（20px で星が赤い十字に見える）。

| round | 観察                                                                                                                                                                                | 変更                                              | 参照             | 終了理由 |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- | ---------------- | -------- |
| 1     | 8 個は 20px で識別できる。`code` の中央の点が要点ではなく飾りに見え、赤い点が 4 個重複する。代案では `database` の上面のベタ塗りが 20px で突出し、`test` の赤チェックが最も騒がしい | なし（比較のみ）                                  | ICON-02、FORM-03 | 指摘あり |
| 2     | 斜線は幅 4 で 13° だと縦棒に見え、25° で長さ 10 だと山括弧との隙間が 1 単位を切る。長さ 8、25° で隙間が約 2 単位に戻る                                                              | `code` の accent を中央の点から角丸の斜線へ変えた | ICON-08、ICON-02 | 指摘なし |

未解決: サイドバーの現在項目はブランド青で描画されるため、青い線と赤い accent が同居する。8 行すべてに赤が 1 点ずつ並ぶので、項目数が増えた資料で赤の縦列が騒がしくなるかは未検証。`code` の斜線と山括弧の隙間は最小値ちょうどで、16px での使用は未検証。
