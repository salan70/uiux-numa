# UX / product レビュー: 授業資料で使う技術アイコン

- 観点: UX / product
- 対象: line-round、line-square、solid、duotone
- 入力: README、variants/、previews/、docs/evaluation/axes.md
- 担当した軸: discoverability、information density

| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |

## 観察

### 推測の記録（手順）

この推測は「Brief を知らない読み手の推測」の代用であり、ユーザーテストではない。
判定の根拠としては、実在の読み手 1 人分にも満たない弱い証拠である。

指示された手順どおり `previews/compare-final-24.png` と `compare-final-96.png` を README の意味の表より先に開いた。
ただしこの 2 枚は列見出しに `ai` `api` `branch` `code` `database` `terminal` `test` `web` の id を印字しており、画像自体が答えを持っていた（compare-final-24.png、compare-final-96.png の 1 行目）。
加えてレビュー依頼文にも 8 個の id が列挙されていたため、意味の集合を知らない状態は最初から作れなかった。

代替として、`variants/<id>/dist/*.svg` 32 個を名前なしで 96px と 24px に描画し、順序を乱数で入れ替えた 8×4 の面を作って読み取った。
この面は作業用に作っただけでリポジトリには含めていない。
結果は 96px で 32/32 が正解の話題に一致したが、これは上の汚染を考えると読みやすさの証拠ではなく、上限値にすぎない。

意味のある記録は正解率ではなく、意味の集合を当てはめる前の「最初に浮かんだ語」である。
最初に浮かんだ語は次のとおりで、4 案に共通する読み替えと、案ごとに分かれる読み替えがあった。

| 意味       | 最初に浮かんだ語（4 案共通） | 案ごとに分かれた読み替え                                                                               |
| ---------- | ---------------------------- | ------------------------------------------------------------------------------------------------------ |
| `terminal` | ターミナル、コマンドライン   | なし。4 案とも一致した                                                                                 |
| `database` | データベース、円柱           | なし。4 案とも一致した                                                                                 |
| `api`      | 交換、同期、送受信           | なし。4 案とも「API」は出ず、往復矢印から通信の一般語に留まった                                        |
| `test`     | 実験、理科、フラスコ         | solid だけ「チェックリスト、提出済み、完了」。フラスコではなく検査票のため                             |
| `code`     | コード、HTML タグ            | line-square だけ「JSON、オブジェクト」。波括弧のため                                                   |
| `ai`       | きらめき、AI、生成           | line-square だけ「菱形、宝石」。凹んだ 4 点星が菱形に置き換わっているため                              |
| `branch`   | 分岐、ノード図               | line-square は「フローチャート、サイトマップ」、solid は 24px で「小文字の h」、duotone は「旗、ピン」 |
| `web`      | 地球、Web、世界              | line-square だけ「ブラウザ、ウィンドウ」。地球儀ではなく窓のため                                       |

取り違えた組み合わせは、同じ 8 個の中での取り違えではなく、8 個の外の語への流出だった。
`api` は 4 案とも「API」に届かず、`test` は 4 案とも「テスト」より先に「実験」または「完了」が出た。
この 2 個は描き方ではなく比喩の選択で決まるという README の Hypothesis は、この推測の範囲では支持された。

### line-round

- 8 個とも単独で 8 個の中の別の話題と取り違えなかった（compare-final-96.png の 1 行目）。
- `branch` は幹に 3 つのノードを置く形で、20px の 4 倍拡大でもノードと枝が分離して見える（line-round-final-sheet.png の branch 行、`variants/line-round/dist/branch.svg`）。
- `code` の `<I>` は山括弧の中にキャレットが入り、単独で「コード、エディタ」に届く（compare-final-96.png の code 列 1 行目）。
- `web` の地球儀は単独で Web に届くが、地球儀は「言語切替」の慣習も持つため、意味は 1 つに定まらない（compare-final-96.png の web 列 1 行目）。
- サイドバー 8 行でアイコンの線がラベルの文字より細く見え、項目名を読む前にアイコンが目に入ることはない（line-round-final-in-context.png のサイドバー）。
- 見出しの 24px はどれも見出し語より軽く、本文の流れを止めない（line-round-final-in-context.png の「今回の目標」「準備」「演習」）。

### line-square

- `ai` は凹んだ 4 点星を 45° の直線に置き換えた結果、単独では「菱形、宝石」としか読めず、生成や AI に届かない（compare-final-96.png の ai 列 2 行目）。
- `branch` の四角ノードは単独で「フローチャート、サイトマップ」に読め、バージョン管理に届きにくい（compare-final-96.png の branch 列 2 行目）。
- `terminal` と `web` はどちらも同寸の枠で、中身だけが違う（line-square-final-sheet.png の terminal 行と web 行）。
- 静止して比べれば中身で区別できるが、サイドバーを上から下へ走査するときは同じ四角が 2 つ現れるので、形による絞り込みが効かない（line-square-final-in-context.png のサイドバー 1 行目と 8 行目）。
- `web` のブラウザ窓は単独で「ブラウザ」に届き、項目名「ブラウザと Web」とはむしろ地球儀より合う（line-square-final-in-context.png の 8 行目）。
- `code` の波括弧は単独で「JSON、オブジェクト」に寄り、ブロック記号を持つ言語の知識を前提にする（README の line-square の未解決と一致）。

### solid

- `test` の検査票とチェックは、単独では「チェックリスト、提出済み、完了」が先に出る（compare-final-96.png の test 列 3 行目、solid-final-sheet.png の test 行）。
- この読み替えは利用画面で実害になる。「演習」の見出しに置かれると「演習が完了済み」に読めて、見出し語と逆の意味を運ぶ（solid-final-in-context.png の「演習」、`variants/solid/Mock.tsx` の 3 つ目の h2）。
- `branch` は 20px で塊になり、ノードと枝の関係が消えて小文字の h に見える（solid-final-sheet.png の branch 行の 4 倍拡大。README の solid の未解決にも同じ記録がある）。
- サイドバーではアイコンが近黒、ラベルが灰色で、濃度が逆転している（solid-final-in-context.png のサイドバー）。
- その結果、項目名より先に目印を読むことになり、8 行を上から追う流れが目印の列に引かれる。
- `code`、`ai`、`web`、`database`、`terminal` は単独でも話題に届き、この 5 個は 4 案の中で最も読み取りが速い（compare-final-24.png の 3 行目）。

### duotone

- `branch` は幹が上下 2 本に切れ、切れ目に赤い節を置き、枝の先に白抜きの円を 1 つ持つ形である（`variants/duotone/dist/branch.svg` の `part-branch-trunktop`、`part-branch-trunkbottom`、`part-branch-accent`）。
- line-round の 3 ノードと違いノードが実質 1 個なので、20px と 32px では「旗」または「ピン」に見え、分岐に読めない（duotone-final-sheet.png の branch 行、duotone-final-in-context.png のスライド箇条書き 1 行目）。
- `api` は戻りの矢じりだけが赤く、往路の黒い矢印より短いので、96px の章扉で往復の対称性が崩れて見える（duotone-final-in-context.png の章扉）。
- サイドバー 8 行すべてに赤が 1 点ずつ並ぶ（duotone-final-in-context.png のサイドバー）。
- 8 行すべてに付くので赤は行を区別せず、現在項目を示す青い太字と役割が重なって競合する。
- 資料ページには他に赤がないため、本文側でも 3 つの見出しの赤が唯一の赤になり、「重要」「警告」の合図として空振りする（duotone-final-in-context.png の「今回の目標」「準備」「演習」）。
- 特に「演習」のフラスコは赤い試料の面積が大きく、24px でも見出し語より先に目に入る（duotone-final-in-context.png の「演習」）。

### 4 案に共通

- 利用画面ではアイコンに必ずラベルが並ぶ。サイドバーは項目名、スライドの箇条書きは文、章扉は章題である（`variants/line-round/Mock.tsx` の `topics` と `ti-slide-list`）。
- そのため「ラベルと並べて分からない」状態は 4 案とも起きず、判定を分けるのは単独推測の可否だった。
- 見出しの前のアイコンだけは例外で、見出し語とアイコンの意味が一致しない。「今回の目標」に `database`、「準備」に `terminal`、「演習」に `test` を置いている（`variants/line-round/Mock.tsx` の 3 つの h2）。
- ここではアイコンが見出し語ではなく「その節で扱う技術」を指しており、サイドバーでの用法と規則が違う。
- `api` の往復矢印は 4 案とも同じ比喩で、単独では「交換、同期」に留まる（compare-final-96.png の api 列 4 行）。
- `terminal` と `database` は 4 案とも単独で話題に届き、描き方を変えても読み取りが落ちない（compare-final-24.png の terminal 列と database 列）。

## 論点

- `api` の往復矢印と `test` のフラスコが、Brief を知らない学生に通じるかは決まっていない。この記録の推測は代用にすぎないので、学生数名にアイコンだけを見せて何の話題か答えてもらう確認が要る。4 案に共通する比喩なので、確認の結果しだいでは 4 案とも同じ差し替えが必要になる。
- 見出しの前のアイコンが何を指すかの規則を決める必要がある。見出し語の言い換えなのか、その節で扱う技術なのかで、9 個目以降の置き方が変わる。現状は後者だが、solid では「演習」が「提出済み」に読めるという実害が出ている。
- duotone の赤を 8 項目すべてに置くかは、赤を何の合図に使うかの決定が先に要る。現在項目だけ、または章扉だけに赤を残す案と比べないと、赤の価値が測れない。
- line-square の `terminal` と `web` が同寸の枠を共有する点は、静止して比べる限り区別できた。サイドバーを走査する条件での確認が要る。
- サイドバーの項目が 8 個から増えた資料での確認が要る。特に duotone の赤の縦列と solid の濃度の逆転は、行数が増えるほど効果が強まる。
- 担当外の気づき: `ai` のスパークルは現在の AI プロダクトの慣習に強く依存する。慣習が変われば 8 個のうちこの 1 個だけが先に古くなるので、brand fit と consistency の観点で見る価値がある。
- 担当外の気づき: `web` の地球儀は「言語切替」の慣習も持つ。授業資料サイトに言語切替がないなら衝突しないが、将来足すなら consistency の観点で再確認が要る。
