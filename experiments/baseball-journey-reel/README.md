## Problem

Baseball Player Journey の UI 刷新（Issue #20）で、動きの設計とゲームの設計の力量を 15 秒で見せる映像がない。
`baseball-journey-app` は画面の情報設計を比べる Experiment で、動きとゲームの手応えは比較軸にしていない。
利用者は 2026-09-30 に、履歴書に添えるショーリールのような 15 秒のモーショングラフィックスを、既存の実装に縛られず要件から作るよう求めた。
形は Web の canvas（動画ファイルは作らない）、UI は映像専用の新しい設計、画面比は縦 9:16 と選んだ。

## Target

作者のモーションデザインとゲームデザインの力量を短時間で見極めたい人（採用担当者、協業相手）を対象にする。
縦型なので、スマートフォンで開くか、SNS の縦の枠で見る場面を想定する。
1 回の訪問で見るのは数回で、映像は画面に入っている間だけ流れる。

## Scope / Domains

対象は animation / motion、visual design、accessibility とする。
映像の中身（場面、曲線、時間、配色、映像の中の UI）と、再生の仕組み（自動再生、停止、減らす設定）を扱う。
製品への移植と Catalog のトップへの組み込みは扱わない。

映像の中の UI は `baseball-journey-app` の `matchday` を参照せず、同じ要件（W、T、C の表）から描き直した。
各場面は要件の ID を 1 つ以上負い、HUD に表示する。

crafting-motion の手順に沿った判断は次のとおり。

- 動かすか: 頻度は「初めて / 稀」に当たる。喜びの予算を使ってよい。
- 目的: 喜びと説明。映像そのものが成果物で、動きの原則とゲームのコアループを見せて説明する。
- 手段: canvas 2D と `requestAnimationFrame`。`catalog-showreel` と同じく、時刻 t から 1 フレームを描く純関数にし、再生、シーク、書き出しで同じ絵を出す。追加の依存は入れない。
- 属性: canvas の中で位置、大きさ、回転、潰しと伸び、透明度、切り抜きの範囲を動かす。
- 曲線と時間: 場面ごとに下の表の値を使う。UI の応答ではなく映像の拍であり、ほとんどが 300ms を超える。UI の押下だけは製品の値（micro 100ms 以内）に合わせる。

## Constraints

- React + TypeScript と canvas 2D で実装し、追加依存を入れない。曲線とばねは `catalog-showreel/variants/ink-ripple/motion.ts` を使う。
- 描画は時刻だけで決める。状態を持つ tween、乱数、経過時間の積み上げを描画に使わない。疑似乱数は `hash`、流線の毎コマの入れ替えはコマ番号の `hash` にする。
- ドット絵の 16×16 の画素は 1 度だけ小さな canvas に焼いて使い回す。時刻に依らない下ごしらえなので、純関数の性質は崩れない。
- 論理座標は 1080×1920 に固定し、表示の大きさには縮尺を掛ける。画素比は 2 を上限にする。
- 書体は LINE Seed JP で、読み込みを待ってから字の幅を測る。電光掲示板の英数字だけ 5×7 のドット文字を矩形で描く。
- 造形は製品の `ui_ux_concepts.md` に従う。太い輪郭、ぼかさずにずらした影、グラデーションと艶を使わない、ドット絵、太字。
- 配色は `color-schemes-material` の `pop-toy`（黄 `#fac400`、青 `#4078e0`、赤橙 `#f37252`、墨 `#120d09`）と、夜の球場と掲示板の深緑で固定する。選択中の配色に追従させない。場面の意味を色で伝えるため。
- `prefers-reduced-motion: reduce` では自動再生しない。題字、惹句、名鑑、次の選手の札が揃った 14.35 秒の 1 枚を置き、再生は利用者が選ぶ。
- 5 秒を超えて自動で動くので、一時停止の操作を常に置く（WCAG 2.2.2）。
- 画面外とタブの裏では時計を止める。戻ったときに途中から飛ばない。
- canvas には `role="img"` と、映像の流れを説明する `aria-label` を付ける。
- canvas の `filter` は使わない。発光とぼかしは段と重ね描きで表す。
- 画面の揺れは 4 コマ以内にし、映像の全体で 5 回に限る。

## Hypothesis

1 個の白球を主役にし、投球、札、入力の指、打率の小数点、投げ上げとして 15 秒を通すと、場面の寄せ集めではなく 1 本の作品に見える。
HUD のダイヤモンドを走者が 1 周する進みを、ゲームのコアループ（CREATE → PLAY → GROW → LEGACY）と 15 秒の進みに兼ねさせると、動きの設計とゲームの設計が同じ 1 つの図で伝わる。
各場面に動きの原則と要件の ID を 1 つずつ割り当てて画面の隅に注記すると、「派手な映像」ではなく「要件から設計された動き」だと伝わる。
最後に投げ上げた白球が冒頭の投球になり、題字の掲示板が冒頭の掲示板に戻ると、15 秒のループの継ぎ目が消える。

HUD:

- 上: `BASEBALL PLAYER JOURNEY — REEL 2026` とタイムコード。
- 下: ダイヤモンドの走者、場面の番号と名前、見せている値、要件の ID、コアループの 4 相、15 秒の進み。

## Evaluation

比較評価は行っていない。
実装者が Web 実行基盤で次を確かめた（2026-09-30）。

- 0.25 秒刻みの 60 コマのシートと主要な場面の拡大で、場面のつながりとループの継ぎ目（14.99 秒と 0 秒）を確かめた。
- 再生は 1 秒で 1 秒進み、一時停止とシークが効く。
- 1080×1920 の 1 コマを PNG まで書き出す所要時間は 8〜19ms で、描画だけならこれを下回る（アプリ内ブラウザ、計測は書き出しの所要時間だけ）。

未確認の軸は、実機の再生でのコマ落ち、Safari と Firefox での字の組み、支援技術での読み上げ、reduced motion の実機での見え方である。
実装した環境の sandbox では headless Chrome を起動できず、preview の画像はまだ置いていない。
