## Problem

Cornix Bonsai は 2026-09-25 に KeySync へ改名した（Issue #15、KeySync の ADR 0035）。
Cornix LP だけでなく、MacBook の内蔵キーボードと Magic Keyboard、今後買う機種のキーマップを 1 か所で管理する道具にするためである。
ロゴは絵文字 🌱 だけで、SVG のマークも favicon も無い。
🌱 は旧名の bonsai から来ており、新しい名前とも道具の役割とも結び付かない。

## Target

KeySync を macOS の Chrome で使い、複数のキーボードの割り当てを編集する個人と、その友人。
ロゴが出る面は 3 つある。
最も頻度が高いのはブラウザのタブ（16px）である。
次がヘッダーの題字（黄のキーキャップ型の箱 36px の中）、最も大きいのが workspace の入口（箱 64px）である。

## Scope / Domains

対象はマーク 1 個と、その lockup の形式である。
domain は `logo-brand-identity`、`visual-design`、`accessibility`。
`logo-brand-identity` を先頭に置き、Catalog に載せない。

比喩の系統と目指す印象は、制作前に利用者が決めた（2026-09-25）。

- 比喩（第 1 世代）: 4 系統すべてで下書きを作る。キーキャップが揃う、文字 K を核にする、同期の矢印や円環、キーボードの盤面を抽象化する。
- 比喩（第 2 世代）: 第 1 世代の 10 案から、利用者が `board-pop`（盤面から 1 個のキーだけが浮く）の方向を選んだ（2026-09-25）。その派生を作る。
- 比喩（第 3 世代）: 第 2 世代から利用者が `pop-tilt` と `pop-confetti` を良いとした（2026-09-25）。あわせて「キーが K や S に見える」か「通常の配列の K と S の位置の色が違う」案を求めた。
- 印象: カラフルで楽しい。Pop Toy 配色と同じ方向で、丸みのある形と太めの面を使う。
- 色: 単色（`currentColor`）を基本にし、Pop Toy の多色版を同じ形で添える。

第 3 世代は、`pop-tilt` の姿勢と `pop-confetti` の色を合わせた `tilt-confetti` を基準にする。
変える軸は、K と S の示し方（色を置く位置、盤面の並び、浮いたキーの刻印）の 3 つで、1 案に 1 つずつ割り当てる。
第 2 世代の 2 案は比較のために残す。

## Constraints

- `<text>`、`var()`、`aria-labelledby` を使わない。`role="img"` と最初の子 `<title>`、id は `part-mark-<role>`、色は `currentColor`（[SVG ツールチェーンの ADR](../../docs/decisions/2026-09-18-svg-toolchain.md)）。
- 白黒 1 色で成立させてから色を考える（`LOGO-07`）。多色版は SVG に色を書かず、part の id の末尾で役割を示し、利用画面の CSS が塗る。`-accent` は黄（primary）、`-accent-2` は青（secondary）、`-accent-3` は赤橙（tertiary）。
- `-accent` は塗りの part だけに付ける。`just svg-compare` は `-accent` の fill だけを塗るためである。
- 黄は白の面に 1.61:1 しかない。多色版で黄の面だけが形を担う案は、明の面で輪郭が弱くなる。
- 本体のヘッダーと入口では、マークは黄の箱（`.logo`）の中に置かれる。単色版は箱の上で黒に近い `on-primary` になる。多色版を使うなら箱を外す。
- viewBox は `0 0 32 32`、live area は `4..28`。favicon の基準が 32px である（`LOGO-07`）。
- Catalog には載せない（[掲載しない Experiment の ADR](../../docs/decisions/2026-09-22-unlisted-experiments.md)）。

## Hypothesis

盤面から 1 個のキーだけが傾いて浮く形は、キーボードを扱う道具であることと、割り当てを変える操作を 1 つの図で示せる。
そこに名前の頭文字 K と S を、色の位置、キーの並び、刻印のどれかで重ねると、図形の比喩のまま名前とも結び付く（`LOGO-02`、uiux-numa-logo の Learnings）。

## Variants

第 3 世代の基準 `tilt-confetti` と 3 案、第 2 世代から残した 2 案、それらを同じ条件で並べる一覧面 `overview` を置く。
採用が決まったら、ほかの案と一覧面は削除し、仮説と軸を「削除した variant」に残す。

| id              | 仮説                                                                              | 変えた軸           | 実装                      |
| --------------- | --------------------------------------------------------------------------------- | ------------------ | ------------------------- |
| `pop-tilt`      | 浮いたキーを傾けると、跳ねている途中に見え、動きと楽しさが増す                    | 浮いたキーの姿勢   | `variants/pop-tilt/`      |
| `pop-confetti`  | 盤面のキーを 3 色に散らすと、Pop Toy のカラフルさがマークだけで伝わる             | 色の配り方         | `variants/pop-confetti/`  |
| `tilt-confetti` | 傾きと色の散らし方を合わせると、動きとカラフルさを両方持てる                      | 基準（2 案の合成） | `variants/tilt-confetti/` |
| `ks-home`       | ホーム段の S と K の位置だけ色を変えると、配列を知る人には名前の頭文字と読める    | 色を置く位置       | `variants/ks-home/`       |
| `k-grid`        | 3×3 の 6 個のキーで K を組み、上の腕だけ浮かせると、字と盤面と操作を 1 つで示せる | 盤面の並び         | `variants/k-grid/`        |
| `k-legend`      | 浮いたキーを大きくして K を刻むと、主役のキーが名前を名乗る                       | 浮いたキーの刻印   | `variants/k-legend/`      |
| `overview`      | 候補を同じ条件で並べると、比べて選べる                                            | 一覧面             | `variants/overview/`      |

原本は `shared/build-marks.mjs` が書き出す。配布用は `just svg-optimize` の出力である。

### 造形のパラメータ

第 2 世代の基準 `board-pop`（削除済み）の値で、`pop-tilt`、`pop-confetti`、`tilt-confetti`、`ks-home` が引き継ぐ。`k-grid` と `k-legend` は、下の座標の導出に別の値を残す。

| 項目      | 値                               | 理由                                                                        |
| --------- | -------------------------------- | --------------------------------------------------------------------------- |
| viewBox   | `0 0 32 32`                      | favicon の基準が 32px（`LOGO-07`）。uiux-numa-logo と同じ                   |
| live area | `4..28`（24 角）                 | 外周 4 を余白に残す（`LOGO-06`）                                            |
| 格子      | 偶数座標                         | 16px（1/2 倍）で整数ピクセルに載る（`SVG-01`）                              |
| キー      | 4 角、角丸 1.25、隙間 2          | 16px で 2px のキーと 1px の隙間。角丸は一辺の約 3/10 でキーキャップに寄せる |
| 盤面      | 4 列 × 3 段、3 段目の中央は幅 10 | 最も少ない段数でキーボードと読める量。スペースバーで段の向きを示す          |
| 色数      | 1（currentColor）+ 役割 3 つ     | 単色で成立させ、多色は利用画面の CSS で塗る                                 |
| 対称軸    | なし                             | 浮いたキーを 3 列目に置き、楽しさと動きを出す（`LOGO-03`）                  |

### 削除した variant

2026-09-25 に利用者が第 1 世代の 10 案から `board-pop` の方向を選んだ。ほかの 9 案はコードを削除し、仮説と軸だけを残す。

- `caps-pair`: 幅の違う 2 個のキーに同じ刻印を置く。軸は比喩（キーが揃う）。2 つの目の読みが残っていた。
- `caps-grid`: 2×2 のうち 3 個が揃い、1 個が輪郭で残る。軸は比喩（キーが揃う）。
- `caps-stack`: 奥のキーの輪郭に手前のキーの面を重ねる。軸は比喩（キーが揃う）。
- `k-cap`: キーキャップの天面に K を抜く。軸は比喩（文字 K）。
- `k-sync`: K の斜画を出る矢印と入る矢印にする。軸は比喩（文字 K）。
- `k-keys`: 縦長のキーと傾けた 2 個のキーで K を組む。軸は比喩（文字 K）。
- `ring-cap`: 中央のキーを 2 本の円弧の矢印が巡る。軸は比喩（同期の記号）。
- `swap-caps`: 対角の 2 個のキーを往復の矢印で結ぶ。軸は比喩（同期の記号）。
- `board-link`: 2 台の段を 1 本の縦長キーが貫く。軸は比喩（盤面）。

2026-09-25 に利用者が第 2 世代から `pop-tilt` と `pop-confetti` を良いとした。基準とほかの 5 案はコードを削除し、仮説と軸だけを残す。

- `board-pop`: 第 2 世代の基準。第 1 世代の案を live area と偶数格子に収めた版。`tilt-confetti` へ引き継いだ。
- `pop-motion`: 浮いたキーの左右に短い線を添える。軸は動きの示し方。
- `pop-ghost`: 空いた位置に細い輪郭を残す。軸は元の位置の示し方。16px で輪郭が見えなかった。
- `pop-bold`: 大きいキー 2 個とスペースバーにする。軸は盤面の粒度。顔の読みが残っていた。
- `pop-stagger`: 2 段目を右へ 2 ずらす。軸は段のずれ。
- `pop-dots`: キーを丸い粒にする。軸はキーの形。16px で基準と見分けられなかった。
