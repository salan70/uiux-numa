## Problem

Catalog のトップで、このリポジトリが動きをどこまで設計できるかを 15 秒で見せる映像がない。
現状のトップは成果物のカードが流れる帯（`marquee-rows`）で、成果物の幅は伝わるが、動きの設計の力量は伝わらない。
利用者は 2026-09-25 に、トップで表示する前提で、履歴書に添えるショーリールのような 15 秒のモーショングラフィックスを求めた。

## Target

Catalog のトップを初めて開く人を対象にする。
採用担当者や協業相手のように、作者の動きの設計力を短時間で見極めたい人を想定する。
1 回の訪問でトップを見るのは数回で、映像は画面に入っている間だけ流れる。

## Scope / Domains

対象は animation / motion、visual design、accessibility とする。
映像の中身（場面、曲線、時間、配色）と、再生の仕組み（自動再生、停止、減らす設定）を扱う。
トップへの組み込みは扱わない。採用が決まってから別に判断する。

crafting-motion の手順に沿った判断は次のとおり。

- 動かすか: 頻度は「初めて / 稀」に当たる。訪問ごとに数回しか見ないので、喜びの予算を使ってよい。
- 目的: 喜びと説明。映像そのものが成果物で、動きの原則（予備動作、潰しと伸び、間隔、行き過ぎ）を見せて説明する。
- 手段: canvas 2D と `requestAnimationFrame`。CSS animation と WAAPI では、全場面を 1 本の時刻から引けない。シーク、コマ送り、動画への書き出しで同じ絵を出すため、時刻 t から 1 フレームを描く純関数にした。05 の床の透視投影も CSS の 3D 変換より 1 つの式で扱える。追加の依存は入れない。
- 属性: canvas の中で位置、大きさ、回転、傾き、透明度、ぼかし、線の長さを動かす。DOM の `transform` と `opacity` に限る仮説は、DOM を動かさない canvas には当たらない。
- 曲線と時間: 場面ごとに下の表の値を使う。ほとんどが 300ms を超える。UI の応答ではなく映像の拍であり、目で追える長さが要るからである。

## Constraints

- React + TypeScript と canvas 2D で実装し、追加依存を入れない。
- 描画は時刻だけで決める。状態を持つ tween、乱数、経過時間の積み上げを描画に使わない。疑似乱数は入力から値を決める `hash` にする。
- 論理座標は 1920×1080 に固定し、表示の大きさには縮尺を掛ける。画素比は 2 を上限にする。
- 書体は Catalog と同じ LINE Seed JP を使い、読み込みを待ってから字の幅を測る。
- 映像の配色は Catalog の既定配色（墨、紙、赤 `#c9171e`、金 `#e6b422`）で固定する。選択中の配色に追従させると、配色によっては赤や金が暗い面で沈み、場面の意味が色で伝わらない。映像の外側の余白と操作だけ `useCatalogColors` で配色に合わせる。
- `prefers-reduced-motion: reduce` では自動再生しない。ロゴと語と副題が揃った 13.6 秒の 1 枚を置き、再生は利用者が選ぶ。
- 5 秒を超えて自動で動くので、一時停止の操作を常に置く（WCAG 2.2.2）。
- 画面外とタブの裏では時計を止める。戻ったときに途中から飛ばない。
- canvas には `role="img"` と、映像の流れを説明する `aria-label` を付ける。
- canvas の `filter` は使わない。Safari で効かない版があり、書き出しと再生で絵が変わる。ぼかしはずらした重ね描きで近似する。

## Hypothesis

1 つの赤い点を主役にし、落下、文字、曲線、部品、帯、ロゴをその点の旅として 1 本につなぐと、場面の寄せ集めではなく 1 つの作品に見える。
各場面に動きの原則を 1 つずつ割り当て、時間と曲線を画面の隅に注記すると、「派手な映像」ではなく「設計された動き」だと伝わる。
最後の点が画面の下へ落ち、冒頭の落下へつながると、15 秒のループの継ぎ目が消える。

## Evaluation

比較評価は行っていない。
全 450 コマを書き出し、0.2 秒刻みのシートと主要場面の等倍で、場面のつながりとループの継ぎ目を確かめた。
書き出しは 450 コマで約 8 秒で、1 コマの描画は 20ms を下回る（headless Chrome、計測は書き出しの所要時間だけ）。
未確認の軸は、実機の再生でのコマ落ち、Safari と Firefox での字の組み、支援技術での読み上げ、reduced motion の実機での見え方である。
