## Problem

Yodoku の現在の UI は、Phase 2 の探索と Phase 3 の調整を積み重ねた結果で、要件から情報設計を導いたものではない。
Issue #19 の反復 1 の点検では、保存に失敗したメモが黙って消える（Y1）、最大の文字サイズで読書中の画面が崩れる（Y2）など 9 件の問題が見つかった。
既存の UI にとらわれず、Yodoku の要件（Yodoku `8dd7e5d` の `docs/specs/**`）から、uiux-numa の Guideline と token に従って UI/UX を作り直す。
最初の round では、情報構造の方向が異なる 3 案を主要画面で並べ、利用者が方向を選ぶ。

## Target

自分の読書を静かに記録したい個人（Yodoku の利用者本人）。
主な利用は、就寝前や朝に紙の本を読みながら iPhone を手元に置く場面である。
読書中は本を見ていて、画面を見るのはメモを書くときと、一時停止や終了のときだけである。
振り返り（本、ふりかえり、検索）は読書の外で、たまに行う。

## Scope / Domains

Yodoku の全画面を対象にする。
ホーム、読書空間、メモ入力、読書の終了、本の追加、本棚、本の詳細、セッション詳細、ふりかえり、検索、削除の取り消し、自動終了の知らせを含む。

variant で変える軸は、情報構造（どこから何へ行くか）と読書空間の構成である。
本詳細、セッション詳細、本棚、ふりかえり、検索、本の追加、メモ入力、終了シートは `shared/` に置いて 3 案で共有し、比較軸にしない。
方向が決まった後の round で、選んだ方向に合わせて作り直す。

縛らない判断（当時の画面の判断として扱い、案ごとに決め直す）:

- 常設のタブを置かない、四隅の操作の意味を固定する（home R-7、画面節）
- 読書中の下部に 3 つの円形操作を置く（reading R-10）
- 読書中は本詳細へ移れない（book-detail の状態節）。3 案とも移れるようにし、別の本を読書中なら「読む」を押せない理由を文字で出す。C-02 は守る。
- 面囲みを使わない、Liquid Glass の範囲、配色、書影が無いときの絵文字（Yodoku DS）
- 日付の年を今年なら省く（book-detail R-15）。Japanese Notation の `2026.09.22` に揃えた。
- ボタンの語形「終了する」「メモする」。UX Writing の語幹と終止形（「終える」「メモ」「読む」）に揃えた。

## Constraints

- SwiftUI（iOS 26）で `platforms/ios` の実行基盤に載せる（[ADR](../../docs/decisions/2026-09-28-ios-runner.md)）。Yodoku のコードには依存しない。
- 固定データは `shared/YodokuAppFixture.swift` に置く。本の書名と著者は実在の本、メモと余韻はこの Experiment のために書いた文で、本文の引用は置かない。
- ドメインの型と導出は Yodoku の `domain.md` と機能仕様の規則を `shared/YodokuAppModel.swift`、`shared/YodokuAppStore.swift` に写し、規則の番号をコメントに残す。本体に無い状態や値を置かない。
- 採用済みの Guideline（UX Writing、Japanese Notation、Information Architecture）に従い、draft の Guideline（Accessibility、States & Feedback、Color、Design Principles）は iOS に読み替えて当てる。
- 最大の文字サイズ、ダーク、動きの抑制で崩れないこと。

### token と Guideline の読み替え

| 対象                            | iOS での扱い                                                                                                                |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| typography                      | LINE Seed JP の woff2 を登録し、`Font.custom(_:size:relativeTo:)` で Dynamic Type に追従させる。1rem = 16pt                 |
| space                           | 値はそのまま。画面の左右は page-inline（24）でなく space-500（20）。393pt 幅で本文の行長を確保するため                      |
| size                            | 押せる領域の最小は target-min（24px）でなく iOS の 44pt                                                                     |
| radius、motion                  | 値はそのまま。動きの抑制では位置と大きさの動きを 0.12 秒のクロスフェードに縮める                                            |
| 色                              | token に色は無い。通常画面は `color-schemes-material` の `sumi` から必要な役割だけを引いた                                  |
| 読書空間の色                    | 4 つの時間帯の縦グラデーションを新しく決めた。本文 7:1、補助 4.5:1、線 3:1 を上端と下端で満たす（下の表）                   |
| Accessibility のフォーカスと h1 | 見出しの特性と VoiceOver のローターに読み替えた                                                                             |
| Accessibility の `dialog`       | 標準の sheet と `confirmationDialog` に読み替えた                                                                           |
| States & Feedback の領域の確保  | セッション詳細の時刻の誤りは、理由の行を常に確保して下の要素を動かさない                                                    |
| Japanese Notation の日付と数    | #19 の G1、G2 は未決なので、Guideline のまま `2026.09.28`、`32 分` で書いた。iOS の標準部品（DatePicker）は OS の書式のまま |

## Hypothesis

読書の外でアプリを開く目的（読み始める、戻る、書いたものを見返す、本を選ぶ）のどれを入口の主役にするかで、同じ要件を満たしながら、読書の静けさと振り返りやすさの釣り合いが変わる。

## Variants

| id          | 仮説                                                                                                                                | 変えた軸                                    | 実装                  |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- | --------------------- |
| `tabs`      | 読む・本棚・ふりかえり・検索を標準のタブに並べ、読書の入口を下端のアクセサリーに常に置くと、どの機能にも 1 回で届き、学ぶことが無い | 情報構造（タブ）、読書空間（再生画面型）    | `variants/tabs/`      |
| `journal`   | 書いた文章を時系列に並べた帳面をホームにすると、文章が主役になり、読書中も書くことが中心になる                                      | 情報構造（帳面）、読書空間（書く欄常設）    | `variants/journal/`   |
| `bookstand` | 1 面に 1 冊だけを立て、左右にめくって本を選ぶと、次に読む本の判断が 1 つずつになり、読書中は目に入るものが最小になる                | 情報構造（1 冊ずつ）、読書空間（中央 1 文） | `variants/bookstand/` |

### 構成

3 案は `shared/` の Store（状態と操作）、画面、部品を共有する。
variant が持つのは、ルート（ナビゲーション）、ホーム、読書空間、ミニ読書プレイヤーの置き方だけである。

```text
YodokuApp<Variant>（入口）          ← Store を作り、起動引数を読む
├─ ルート                            ← tabs: TabView、journal / bookstand: NavigationStack 1 本
│  ├─ ホーム                         ← variant ごと
│  └─ 行き先（YK.Route）             ← shared: BookDetail、SessionDetail、Bookshelf、Statistics
├─ 検索                              ← tabs: 検索タブ、journal: 帳面を引いて出す、bookstand: シート
├─ 本の追加（YK.BookLookup）         ← shared のシート
├─ ミニ読書プレイヤー                ← tabs: タブのアクセサリー、journal / bookstand: 下端の Glass
└─ 読書空間（全画面）                ← variant ごと。終了シートとメモ入力は shared
```

### 試し方

```sh
just ios-run yodoku-app/tabs -fixture idle
```

| 起動引数          | 状態                                                            |
| ----------------- | --------------------------------------------------------------- |
| `-fixture <mode>` | `empty`、`idle`（既定）、`active`、`paused`、`autoEnded`        |
| `-minimized`      | 進行中の読書を最小化した状態で始める                            |
| `-memoFailure`    | 次のメモの保存を失敗させる                                      |
| `-lookupOffline`  | 本の検索を失敗させる                                            |
| `-route <name>`   | 起動直後に `book`、`session`、`shelf`、`stats` を開く（撮影用） |
| `-ending`         | 起動直後に終了シートを開く（撮影用）                            |

比較画像: [ホーム](previews/compare-idle.png)、[読書空間](previews/compare-reading.png)、[最小化](previews/compare-minimized.png)（左から `tabs`、`journal`、`bookstand`）。

### モックの限界

- 永続化しない。起動のたびに固定データから作り直す。
- 書影は取得せず、書名を刷った無地の表紙で代える。本の検索は固定の候補から探し、楽天と NDL を呼ばない。
- 起動時と復帰時の自動終了の判定は、画面の表示時にだけ行う。
- 触覚、Liquid Glass の見え方、動きの滑らかさは、シミュレータの Debug ビルドで見ただけで、実機では確かめていない。
- カテゴリーの管理、アプリの起動時のエラー（Y6）は置いていない。

## Evaluation

`docs/evaluation.md` の多観点評価は行っていない。
実装者がシミュレータ（iPhone 17、iOS 26.1）で次を確かめた（2026-09-28）。

- 3 案のホーム（`idle`、`active` の最小化、`empty`）、読書空間（`active`）、終了シート、自動終了の知らせを撮った。
- `journal` で本詳細、セッション詳細、ふりかえり、本棚を開き、ダークの本詳細を撮った。
- `tabs` の読書空間を最大の文字サイズ（accessibility-extra-extra-extra-large）で撮り、事実の値が 1 字ずつ折り返さないことを見た。下部の操作が本文に重なる点は残っている。

VoiceOver の読み上げ、動きの抑制、メモの保存失敗と本の検索失敗の実操作、`journal` と `bookstand` の最大の文字サイズは確かめていない。
