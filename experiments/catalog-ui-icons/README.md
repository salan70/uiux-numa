## Problem

Catalog が自分の UI で使うアイコンは `apps/catalog/src/components/icons.tsx` に JSX で直書きされている。
正本の SVG ファイル、機械検査、比較シート、利用画面の preview、造形の理由の記録がどれもない。
形を直すときに根拠が辿れず、他プロジェクトへ持ち出す単位にもなっていない。

利用者は現行の形に満足していない。
再現ではなく、`crafting-svg` の手順で作り直す。

`class-tech-icons` と `hako-feature-icons` は最小サイズが 20px 以上、または架空のプロダクトを対象にしていた。
Catalog は実利用のプロダクトで、最小 16px の Button の中にもアイコンが入る。
16px を最小に置いた組は、このリポジトリでまだ作っていない。

## Target

Catalog（<https://uiux.oda79.me/>）の利用者。
成果物を探しに来て、ナビを開閉し、配色カードから詳細を開き、配色を前後に送る。
アイコンは操作の主役ではなく、文字の隣に置く補助である。

## Scope / Domains

対象領域は iconography、visual-design、consistency、accessibility。

対象は Catalog の UI アイコンのうち 4 asset にする。

| asset        | 用途                             | 表示サイズ |
| ------------ | -------------------------------- | ---------- |
| `detail`     | 配色カードの「役割をすべて見る」 | 20px       |
| `sidebar`    | ナビの開閉トグル                 | 20px       |
| `arrow-prev` | 配色の前送り Button の leading   | 16px       |
| `arrow-next` | 配色の後送り Button の trailing  | 16px       |

勾玉（配色セレクタ）と明暗 3 状態は対象外にする。
勾玉は 2 色で、SVG 側で色の役割を持つため、単色の組とは別の判断が要る。

variant は 1 案だけにする。
方向（柔らかく丸い線画）は利用者が先に決めた。
変える軸を持たないので、反復で磨いて記録する。

## Constraints

- `viewBox` は `0 0 24 24` にする。Catalog の既存のアイコンと外部 SVG の組に揃える。
- 単色にする。`currentColor` だけを使い、`var()` は使わない（resvg が描画できない）。
- 最小表示サイズは 16px にする。Button の icon 枠は `1em` で、Button の `font-size` は `--typography-control-font-size: 1rem` である。
- 最大表示サイズは 20px にする。`.app-shell .icon` は `1.25rem` である。
- 寸法と線の属性は利用画面の CSS が持つ。SVG は形だけを持つ。
- 開閉や選択で形を変えない。状態で押し先の寸法を動かさない。

## Hypothesis

座標を比例（黄金比と keyline）から導き、0.75 格子へ丸めて誤差を記録すれば、
「見た目で決めた」座標を残さずに 1 組を揃えられる。

比例と格子が衝突したときは、16px での可読性を上位に置く。
黄金比は 18 の live area では 0.75 格子上に ±3.0% で載る場合と、5% 以上外れる場合がある。
外れた箇所を記録に残せば、次の組で当てる場所を選べる。

| `round-soft` | 線幅 1.5、丸い端点、外形 18 の線画で、16px でも 4 個が 1 組に見える | 見た目（造形） | `variants/round-soft/` |

### 造形のパラメータ

1 組で 1 つの値に固定する（`docs/principles/icon-set-consistency-by-few-parameters.md`）。

| 項目               | 値                                  | 参照    |
| ------------------ | ----------------------------------- | ------- |
| viewBox            | `0 0 24 24`                         | ICON-04 |
| 外形（live area）  | 3..21 の 18×18。padding 3           | ICON-04 |
| 線幅               | 1.5                                 | ICON-05 |
| 端点と角           | `round`。root で 1 回だけ指定する   | ICON-07 |
| 軸に平行な線の中心 | `0.75 + 1.5n`                       | ICON-09 |
| 内側の最小隙間     | 1.5 以上                            | ICON-08 |
| 色                 | `currentColor` 単色。塗りは使わない | ICON-10 |

padding を 2 ではなく 3 にした理由を残す。
最小表示は 16px で倍率は 2/3 である。
軸に平行な線の外縁 `e` が整数ピクセルに乗る条件は `e × 2/3 ∈ ℤ`、すなわち `e` が 1.5 の倍数であることである。
ICON-04 が挙げる padding 2 は 1.5 の倍数ではない。
その内側で最も近い 1.5 の倍数は 3 なので、このシステムの値を 3 にした。

同じ条件から、12 を中心に対称な外形の幅 `w` は `12 ± w/2` が 1.5 の倍数になる必要がある。
つまり `w` は 3 の倍数（3、6、9、12、15、18）しか取れない。
keyline（ICON-06）の理論値をこの中へ丸めることになる。

### 座標の導出

すべての座標を「比例で決める → 0.75 格子へ丸める → 誤差を残す」の 3 段で決めた。
`source/*.svg` の各 path の直前にも同じ導出をコメントで置いている。

| 幹の長さ | keyline | live area いっぱいの 18           | 18（中心 3.75..20.25） | 0                  |                                                                                                                |
| 幹の軸   | 格子    | `0.75 + 1.5n`                     | `y=11.25`              | 箱の中心から −0.75 | `y=12` は外縁 11.25/12.75 となり、16px で幹だけが薄く出た（round 2）。囲み形がないので中心のずれとして見えない |
| 頭の角度 | √2      | 45°（正方格子の対角）             | 45°                    | 0                  | 斜線なので座標の整列は効かない                                                                                 |
| 頭の深さ | 黄金比  | 21 − 18 ÷ φ² = 14.124（後端の x） | 14.25                  | **+3.0%**（比）    | 尾 11.25 : 頭 6.75 = 1.667。5% 以内なので φ を採用した                                                         |

#### 黄金比を採れなかった箇所

| 箇所                | 理論値 | 採用値 | ずれ   | 代わりに採った根拠                        |
| ------------------- | ------ | ------ | ------ | ----------------------------------------- |
| detail の内容の高さ | 9.27   | 10.5   | +13.3% | 16px での隙間の可読性（ICON-08）          |
| sidebar の枠の高さ  | 14.4   | 12     | −16.7% | 円との見かけの大きさの釣り合い（ICON-06） |
| sidebar の角丸      | 2.427  | 2.25   | −7.3%  | 線幅 × 1.5 の単純整数比（3:2）            |

18 の live area を 0.75 刻みで割ると、取れる比は離散になる。
黄金分割 11.124 : 6.876 は 11.25 : 6.75 に丸まり +3.0% で載るが、
それ以外の分割では最寄りの格子でも 5% を超える。
黄金比が使えるのは、18 を 2 つに割る 1 か所だけだった。

### 反復の記録

| round       | 観察                                                                                                                                                                         | 変更                                                                                 | 参照                                              | 終了理由                               |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------- | -------------------------------------- |
| 0（下書き） | `detail` の比喩 3 案を 16px で比較した。円の i は点と棒が隙間 1.5 で癒着した。三点リーダは見かけの重さが軽い。山形は明快だが「下へ開く」で用途と合わない                     | 比喩を「円の中の i」に決めた。隙間を 2.25 へ広げた                                   | ICON-02、ICON-08、`metaphor-decides-before-style` | 利用者が比喩を選んだ                   |
| 1           | `sidebar` の枠 18×15 が `detail` の円（外形 18）より重く見えた。`arrow` の幹が 16px で頭より薄く出た                                                                         | 枠の高さと幹の位置を 2 案ずつ描いて比べた                                            | ICON-06、ICON-09                                  | 観察を案に変えた                       |
| 2           | 枠は 18×12 が円と釣り合った。幹は `y=11.25` が 16px で実線になり、`y=12` は灰色に潰れた。`detail` の棒も同じ問題を持つが、字面ごと 0.75 寄せると輪が箱の中で左に寄って見えた | `sidebar` を 18×12、`arrow` の幹を `y=11.25` にした。`detail` は `x=12` のまま残した | ICON-06、ICON-09                                  | 囲み形の有無で扱いを分ける規則に落ちた |

round 2 で決めた規則を残す。
**囲み形を持つ asset は箱の中心（12）に置く。囲み形を持たない asset は格子を優先して 0.75 ずらしてよい。**
`detail` と `sidebar` は囲み形を持ち、`arrow` は持たない。

`sidebar` は枠と桁の外縁がすべて 1.5 の倍数に載るため、ずらす必要がなかった。

## Evaluation

観点別の評価は行っていない。
現行の `apps/catalog/src/components/icons.tsx` の 4 asset を単体 SVG に起こし、`round-soft` と 16 / 20 / 24px で並べて利用者が見比べた。
16px は resvg のラスタライズを nearest-neighbor で 8 倍に拡大し、ピクセルの当たり方を見た。

未確認の軸は、支援技術による読み上げ、16px 未満での見え方、Catalog 以外のプロダクトへの適合である。

## Decision

`round-soft` を採用する。

- 判断者: リポジトリの所有者
- 判断日: 2026-09-22
- 根拠: 利用者が現行と `round-soft` を 16px で見比べて選んだ。現行の `arrow` は幹が `y=12` にあるため 16px で 1px の線が半ピクセルにまたがり、灰色ににじんで頭より薄く出る。`round-soft` の `y=11.25` は実線になり、頭と同じ濃さで揃う。`detail` も点と棒の隙間が 1.5 から 2.25 に広がり、16px で i の字が読める。

採用に伴い `apps/catalog/src/components/icons.tsx` の `DetailIcon`、`SidebarIcon`、`ArrowIcon` を差し替える。
`MagatamaIcon` と `AppearanceIcon` はこの Experiment の対象外のため、現行の形のまま残る。

## Rejected reasons

却下した variant はない。
`round-soft` の 1 案だけを作り、反復で磨いた（Variants の「反復の記録」）。

round 0 で却下した `detail` の比喩 2 案の理由を残す。

- 三点リーダ: 16px で見かけの重さが他の 3 asset より軽い。
- 山形（シェブロン）: 形は明快だが「下へ開く」を意味し、詳細を開く用途と合わない。

## Learnings

- 16px を最小に置くと、24 の viewBox で使える座標は大きく減る。軸に平行な線の外縁は 1.5 の倍数、対称な外形の幅は 3 の倍数しか取れない。ICON-04 の padding 2 も、ICON-06 の keyline 20 も、そのままでは載らない。値はシステムごとに決め直す、という ICON-04 と ICON-05 の但し書きが実際に効いた。
- 箱の対称軸（12）は線の中心の格子（`0.75 + 1.5n`）に載らない。中心を通る 1 本の線は、対称性か 16px の鮮明さのどちらかを捨てることになる。囲み形の有無で分けると、どちらを捨てるかを規則にできる。
- 黄金比は 0.75 格子の上では、18 を 2 つに割る場合だけ 5% 以内に載った。3 つ以上の要素を持つ形（detail）では、最寄りの格子でも 10% を超える。比例を根拠にできる場所は、格子の粗さが決める。
- 零長の線に丸い端点を打つと、塗り要素を足さずに点を描ける。SVGO は `h0` を `z` に書き換える。閉じた零長の subpath の扱いは描画系で揺れうるが、resvg と Chrome の両方で同じ点として描かれることを確かめた。
- 揺れるのは描画系だけではない。最適化系も揺れる。svgo 4.0.1 の `convertPathData` は零長の subpath を「無用」と見なして `path` ごと消し、4.1.0 は `z` に畳んで残す。`h0`、`z`、`v0`、`h0z` のどの書き方でも 4.0.1 は消す。造形の手段が最適化の既定に依存していたということで、`convertPathData: { removeUseless: false }` で明示的に守る形に直した（[ADR](../../docs/decisions/2026-09-22-svgo-keeps-zero-length-subpaths.md)）。`svg-optimize` の `part-*` ID の一致検査がこれを検知した。検査が造形の前提を守った例である。
