## 現在地

2026-10-01 時点。
進め方と判断の記録は [#21](https://github.com/salan70/uiux-numa/issues/21) にある。

- 判断待ち: round 1 の 3 案から、利用者が方向を選ぶ。
- 次の一手: 選んだ方向で、残りの画面（条件の設定、履歴、設定、広告の導線）と状態（オフライン、該当なし）を詰める。
- 読むもの: この README の「要件の整理」「Variants」「試し方」。

## Problem

.389 / プロ野球クイズの現在の UI は、Design System v2（#894）で見た目を揃えたが、画面の構成と体験の芯は初期の版から引き継いでいる。
既存の UI と実装の都合にとらわれず、要件（`salan70/389-app` `10adac47` の `docs/spec/`、`docs/design/`、ドメインのコード）から作り直す。
最初の round では、グラフィック、ゲーム、モーションの観点で主要画面を作り込んだ 3 案を Flutter で並べ、利用者が方向を選ぶ。
そこから逆算して、uiux-numa の Guideline と token、.389 の実装へ落とし込む。

## Target

NPB の野手の成績を眺めるのが好きで、数字から選手を当てる遊びを毎日少しずつ楽しむ人。
主な利用は、19 時の今日の1問の通知を受けたときと、すき間の時間にノーマルを何問か解く場面である。
最も多い操作は 1 マスを開けることで、1 問に数回から数十回ある。
回答は 1 問に 1〜数回、結果は 1 問に 1 回、マイ成績はたまに見る。

## Scope / Domains

主要画面を対象にする。
ホーム、クイズ（ノーマル、今日の1問）、回答、結果、マイ成績を含む。
条件の設定、履歴、設定、広告の導線、初回の同意と通知の許可は round 2 に回す（下の「置き場所」）。

variant で変える軸は、成績表の見立て（何に見せるか）と、それに従う見た目、動き、情報構造である。
出題の規則、ランクの判定、記録の値は `shared/` に置いて 3 案で共有し、比較軸にしない。

## Constraints

- 製品のコードには依存しない。出題の規則とランクの判定は `shared/data.dart` に写し、出典の commit を書いた。
- 成績は `data/build.mjs` で `salan70/389-app` `42d79695` の `tools/npb_data_scraper/seasons/end2025` から `shared/data.g.dart` に書き出した。出題は製品の既定の条件（通算 300 試合、300 安打、50 本塁打）を満たす 54 人、候補は 393 人の全員である。
- 文字は実行基盤にある LINE Seed JP だけを使う。発車標や中継に合う等幅や斜体の書体は、token に足すかを方向が決まってから判断する。
- 遊んだ記録は `shared/profile.dart` の固定の記録で、製品の集計の値の形だけを写した。
- 動きは `MediaQuery.disableAnimations` で止まる。止めたときは終わりの状態を出す。

## Hypothesis

成績表を「何かの物」に見立て、1 マスを開ける手応えと正解の瞬間に固有の動きを与えると、同じ規則のままで 1 問を解く楽しさと、もう 1 問への動機が上がる。
あわせて、開示の代償（ランクが下がる）を最中に見せると、開けるか答えるかの駆け引きが生まれ、ランクに価値が出る。

## Variants

| id          | 軸                                                                                     | 向く状況                                                    | 代償                                                                                  |
| ----------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `cardback`  | 成績表を野球カードの裏面にし、正解でカードを表へ返す。ランクをレア度として集める        | 集める楽しさで続けたい。1 問の結果を物として残したい        | 紙の明るい面が広く、夜の通知で開くと眩しい。カードの枠のぶん表が小さい                |
| `splitflap` | 成績表を発車標の札にし、全画面を 1 枚の盤で描く。開示、正解、画面の切り替えを札の回転だけで表す | 毎日の短い儀式として遊びたい。タイマーで眺めて当てたい      | 札の 1 文字の幅に収めるため、球団を 1〜2 文字に略す。漢字の名前は札では小さい         |
| `broadcast` | 成績表を中継の成績テロップにし、遊ぶ人を打者に見立てる。外れはストライク、今日の1問の 3 回はアウト | 野球の観戦の気分で遊びたい。打率の比喩を前に出したい        | 斜めの帯と傾けた太字が強く、長く見ると疲れる。斜めの切り欠きのぶん帯の幅が減る        |

3 案の共通点:

- クイズの最中に「いま当てれば」のランクと、下がるまでのマス数を出す。`cardback` は割合の帯の目盛り、`splitflap` は札、`broadcast` はスコア表示の中に置く。
- 外れた名前を画面に残し、回答の候補では外れを消して選べなくする。
- 開示の動きは 1 問に何十回もあるので短く（220〜400ms）し、正解の動きだけを長く（600〜900ms）する。

### 実装

- `variants/cardback/index.dart`: 開示はインクの押印（文字が縮みながら出て、輪が広がる）。正解は 3D で裏返し、SS は虹色の枠を回す。ホームの今日の1問は封をしたパックで、ゆっくり揺れる。
- `variants/splitflap/index.dart`: 開示は 1 文字ずつ上半分が倒れて下半分が起きる回転を数回くり返す。ホームと結果は盤を空から順に回して出す。回答は選んだ名前を盤の行に回してから判定する。
- `variants/broadcast/index.dart`: 開示は白い光が左から拭く。正解は赤、金、紺の斜めの帯が画面を横切る場面転換。外れは赤い帯「ちがう！」が横切る。

## Evaluation

round 1 は利用者が 3 案を操作して方向を選ぶ。

確かめたこと:

- `just flutter-check` が通る。
- 402×874 で、ホーム、クイズの途中、外れの直後、正解、今日の1問、3 回外れ、マイ成績を撮影し、崩れが無いことを見た（`previews/`）。撮影は動きを止めた状態である。

確かめていないこと:

- 動きの実機での手触りと、連打したときの見え方（`splitflap` は回転の途中で次の開示が来ると、回転の列を差し替える）。
- 文字を大きくしたとき、VoiceOver の読み上げ、コントラストの数値。
- ライトの配色。3 案とも見立ての物に合わせて端末の明暗に関わらず同じ配色にしており、ライトを持つかは方向と合わせて決める。

## 試し方

`just flutter-dev` を起動し、`http://localhost:5185/?compare=389-app` で 3 案を並べて操作する。
1 案だけなら `?variant=389-app/<id>` で開き、端末の枠の外の操作盤から各画面へ移れる。

起動の query:

- `screen=<行き先>`: `home`、`quiz`、`quizMid`、`answer`、`wrong`、`result`、`daily`、`dailyFail`、`stats`
- `user=new`: 記録が無い初めての人
- `daily=done`: 今日の1問を済ませた後
- `player=<名前>`: 確かめるための出題の選手（既定は `柳田 悠岐`）
- `reduceMotion=1`: 動きを止める（実行基盤の query）
