## 現在地

2026-10-02 時点。
進め方と判断の記録は [#21](https://github.com/salan70/uiux-numa/issues/21) にある。

- 採用: `scoreboard`（現行の構成を磨く）。round 3 から、配色、配置、要素の大きさと形、アイコンを 1 つずつ磨いている。
- 判断待ち: round 3 の直しを利用者が確かめ、次に磨く項目を選ぶ（下の「次に磨く候補」）。
- 読むもの: この README の「反復の記録」「次に磨く候補」「試し方」。

## Problem

.389 / プロ野球クイズの現在の UI は、Design System v2（#894）で見た目を揃えたが、画面の構成と体験の芯は初期の版から引き継いでいる。
要件（`salan70/389-app` `10adac47` の `docs/spec/`、`docs/design/`、ドメインのコード）から、主要画面の体験を作り直す。
round 2 からは、利用者が気に入った既存のテイスト（`DESIGN.md` の Design System v2）を前提にし、見た目は変えずにゲームの仕組み、情報構造、動きで案を分けた。
round 3 からは、採用した `scoreboard` を細部まで磨く。
そこから逆算して、uiux-numa の Guideline と token、.389 の実装へ落とし込む。

## Target

NPB の野手の成績を眺めるのが好きで、数字から選手を当てる遊びを毎日少しずつ楽しむ人。
主な利用は、19 時の今日の1問の通知を受けたときと、すき間の時間にノーマルを何問か解く場面である。
最も多い操作は 1 マスを開けることで、1 問に数回から数十回ある。
回答は 1 問に 1〜数回、結果は 1 問に 1 回、マイ成績はたまに見る。

## Scope / Domains

主要画面を対象にする。
ホーム、クイズ（ノーマル、今日の1問）、回答、結果、マイ成績を含む。
条件の設定、履歴の削除、設定、広告の導線、初回の同意と通知の許可は、方向が決まってから置く（下の「置き場所」）。

round 2 の variant で変えた軸は、1 問の結果に何の意味を持たせるか（ゲームの仕組み）と、それに従う情報構造と結果の動きである。
v2 の造形（`shared/ds.dart`、`shared/icons.dart`）、クイズの画面（`shared/quiz_screen.dart`）、出題の規則とランクの判定（`shared/data.dart`）は `shared/` に置く。

縛らない判断（現行の画面の判断として扱い、決め直した）:

- ランクを結果の画面で初めて見せる。3 案ともクイズの最中に「いま当てたときのランク」と「下がるまでのマス数」を、SS〜C の 5 枠の札で出した（下の Hypothesis）。
- 外れをダイアログで知らせる。表の上に pink の帯を 1.6 秒だけ降ろし、閉じる操作を無くした。外れた名前は目盛りの下に残し、回答の候補では消して選べなくした。
- 新しく開いたマスが他と同じ色で出る。開いた瞬間だけ pink の枠で大きく出し、600ms で cyan の定位置へ戻して、どこが開いたかを追えるようにした。
- 結果の画面が成績表に一言を足しただけである。3 案とも、正誤の札、選手名、ランクを上に置き、表は下に縮めた。
- 下端の帯の補助に退出がある。v2 の「補助｜回答｜補助」は守り、補助を「すべて表示」と「次を表示」にした。あきらめる（製品の退出）は、製品と同じくヘッダーの左の × に置いた。今日の1問は「すべて表示」が使えないので、補助を「次を表示」だけにした。
- 結果の表を全部同じ色で見せる。開いたマスを cyan、開かずに済んだマスを白にして、何個の手がかりで当てたかを表の上でも読めるようにした。
- ホームのユーティリティの行（設定、広告の非表示）。round 2 では置かない。置き場所は方向と合わせて決める。

## Constraints

- 製品のコードには依存しない。出題の規則とランクの判定は `shared/data.dart`、v2 の造形は `shared/ds.dart` に写し、出典の commit を書いた。
- 成績は `data/build.mjs` で `salan70/389-app` `42d79695` の `tools/npb_data_scraper/seasons/end2025` から `shared/data.g.dart` に書き出した。出題は製品の既定の条件（通算 300 試合、300 安打、50 本塁打）を満たす 54 人、候補は 393 人の全員である。製品と同じく、通算の行を表の最後に含める。
- 書体は製品と同じ RocknRoll One と Oxanium を `fonts/` に置き、実行基盤に登録した（[ADR](../../docs/decisions/2026-10-01-flutter-product-fonts.md)）。
- アイコンは製品の SVG（`DsSvgIcon`）のパスを `shared/icons.dart` に写し、CustomPainter で描く。SVG を読む依存は足さない。
- 遊んだ記録は `shared/profile.dart` の固定の記録で、製品の集計の値の形だけを写した。
- 動きは `MediaQuery.disableAnimations` で止まる。止めたときは終わりの状態を出す。

## Hypothesis

1 問の結果に、正誤とランクより強い意味（自分の打撃成績、名鑑の空き）を持たせると、もう 1 問への動機と、少ない開示で当てる動機が上がる。
あわせて、開示の代償（ランクが下がる）を最中に見せると、開けるか答えるかの駆け引きが生まれる。

## Variants

| id           | 軸                                                                                             | 向く状況                                                 | 代償                                                               |
| ------------ | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------ |
| `scoreboard` | 現行の情報構造と結果の意味のまま、最中の目盛り、外れの帯、ランクが着地する結果で体験の芯を磨く | 今の遊び方を変えずに手触りを上げたい。移植の量を抑えたい | 1 問の結果がランクと正解率の数字にしか残らず、続ける動機は今と同じ |

削除した variant（コードは [`f2afbe4`](https://github.com/salan70/uiux-numa/tree/f2afbe4/experiments/389-app) にある）:

- `atbat`: 1 問を 1 打席とし、ランクを打球（SS は本塁打〜C は内野安打、不正解は凡退）に読み替えた。結果で走者が塁を回り、打率と長打率が動いた。
- `collection`: 球団別の選手名鑑を主役にし、当てた選手が名鑑の空きを埋めた。結果でランクの色の札が球団の升へ飛んだ。

### 実装

- `variants/scoreboard/index.dart`: 結果のランクは 180ms 待ってから、2.4 倍から縮みながら着地する（700ms）。上のランクまで何マス足りなかったかを添える。
- `shared/quiz_screen.dart`: クイズの画面。round 2 で 3 案が共有した形のまま、目盛りの読み替えや表の上の帯を引数で受ける。
- `shared/icons.dart`: 線画アイコン。製品の 14 個と、描き足した 6 個。

## Evaluation

round 2 は利用者が 3 案を操作し、`scoreboard` を選んだ。round 3 からは、利用者が直しを確かめ、次に磨く項目を選ぶ。

確かめたこと:

- `just flutter-check` が通る。
- 402×874 で、ホーム、クイズの途中、今日の1問、正解、3 回外れ、プレイ記録を撮影し、崩れが無いことを見た（`previews/scoreboard.png`）。撮影は動きを止めた状態である。
- 実時間のブラウザで、開示の動き、外れの帯（回答のシートで外れの名前を選ぶ操作）、狭い画面のボタンからの画面の移動を確かめた（round 2）。

確かめていないこと:

- 実機での手触り。文字を大きくしたとき、VoiceOver の読み上げ、コントラストの数値。
- 全部開けたとき、何度も外したとき、通算の行だけが残ったときの目盛りの言い回し。

### 次に磨く候補

round 3 の点検で見つけ、まだ直していない点。利用者が選んだものから進める。

- アイコン: 製品の `baseball` は 20px だと縫い目が合流して「Y」に見える。縫い目を外へ開く形に描き直すか、製品のまま残すかを決める。
- 配色: 目盛りの SS〜C の札は、いまの枠だけランクの色で塗り、ほかはランクの色の文字にしている。ランクの色は v2 で「チャートとラベル専用」なので、文字に使ってよいかを決める。
- 配置: クイズで、外れた名前の札が出ると表が 1 行ぶん下がる。札を目盛りの右に寄せるなど、表を動かさない置き方にする。
- 大きさと形: 表の行の高さ（34）では、15 年を超える選手で下端の帯に通算の行が隠れる。行を詰めるか、通算の行を表の下に固定する。
- 文言: 結果の「これ以上ない当て方です」など、ランクごとの一言を揃える。
- 置いていない画面: 条件の設定、履歴の削除、設定、広告の導線、オフライン、該当なし。

## 試し方

`just flutter-dev` を起動し、`http://localhost:5185/?variant=389-app/scoreboard` で開く。端末の枠の外の操作盤から各画面へ移れる。
スマホでは [Artifact](https://claude.ai/artifact/QrkzLp35j2DAAPA5GSpqTP) で開く（非公開）。右端の丸いボタンから各画面へ移れる。
Artifact はビルドで既定の案を渡す（`--dart-define=RUNNER_QUERY=variant=389-app/scoreboard`）。

起動の query:

- `screen=<行き先>`: `home`、`quiz`、`quizMid`、`answer`、`wrong`、`result`、`daily`、`dailyFail`、`stats`
- `user=new`: 記録が無い初めての人
- `daily=done`: 今日の1問を済ませた後
- `player=<名前>`: 確かめるための出題の選手（既定は `柳田 悠岐`）
- `reduceMotion=1`: 動きを止める（実行基盤の query）

## Decision

`scoreboard` を採用する（2026-10-02、利用者の判断）。
現行の情報構造と v2 の造形を保ち、配色、配置、要素の大きさと形、アイコンを 1 つずつ磨いて、.389 へ移す。

## Rejected reasons

- `atbat`、`collection`: 利用者は現行を磨く方向を選んだ。2 案に固有の不採用の理由は挙げていない。
- round 1 の `cardback`、`splitflap`、`broadcast`: 利用者は既存の .389 のテイストが良いとした。
