## Problem

DocBridge（`salan70/docbridge`）は Markdown 文書とコードを `@doc` / `@code` の注釈で双方向に結び、乖離を検査する CLI である。
ロゴは無く、README は文字とバッジだけで始まる。
npm と GitHub の一覧では、同種の道具（ESLint、Prettier、typedoc）にマークがあり、DocBridge だけが顔を持たない。

## Target

DocBridge を npm で導入する開発者と、GitHub で README を読む人。
ロゴが出る面は 2 つある。
GitHub README のヘッダ（マークと wordmark の横組み、明暗）と、favicon / npm の avatar（16〜64px の正方形）である。

## Scope / Domains

対象はマーク 1 個と、その lockup の形式である。
domain は `logo-brand-identity`、`visual-design`、`accessibility`。
`logo-brand-identity` を先頭に置き、Catalog に載せない。

比喩、印象、色、使い先は、制作前に利用者が決めた（2026-09-30）。

- 比喩: 橋そのもの。2 つの岸や `@` の記号、文字組ではない。
- 印象: 開発者ツールらしく淡々と。線が細めで幾何学的。
- 色: 単色。黒と白の反転を前提にし、色は後で足す。
- 使い先: GitHub README のヘッダ、favicon / npm のアイコン。

世代ごとに、利用者の判断を受けて軸を変えた。

1. 橋の構造（アーチ、桁、吊り）と、面か線か。
2. 利用者が「名前の文字を自然に組み込みたい。D と B が橋の形に近い」と求めた。D と B は bowl がアーチなので、字を 90° 倒して stem を桁、bowl をアーチにする。軸は文字（D か B）、倒す向き（bowl が桁の上か下か）、桁の張り出し。
3. 利用者が第 2 世代を「方向性いい感じ」とし、「全体的に丸みを帯びさせて」と求めた。軸は丸みの有無だけ。
4. 利用者が第 3 世代を「概ねいい感じ」とし、「数式や幾何学模様で、より美しく」と求めた。bowl が桁の上にある D と B を基準に、作図の体系を 1 つに絞って引き直す。軸は D の直線部の有無、同心の帯の追加、B の線の均一化。

## Constraints

- `<text>`、`var()`、`aria-labelledby` を使わない。`role="img"` と最初の子 `<title>`、id は `part-mark-<role>`、色は `currentColor`（[SVG ツールチェーンの ADR](../../docs/decisions/2026-09-18-svg-toolchain.md)）。
- 白黒 1 色で成立させる（`LOGO-07`）。色を足すなら part の id の末尾 `-accent` で役割を示し、利用画面の CSS が塗る。
- viewBox は `0 0 32 32`、live area は `4..28`。favicon の基準が 32px である（`LOGO-07`）。
- 面の縁は偶数座標に置き、16px で整数ピクセルに載せる（`SVG-01`）。fillet の接点だけは例外で、小数座標を許す。
- wordmark は利用画面の HTML テキストで組む。フォントは未決で、モックは `tokens/typography` の sans を使う。
- Catalog には載せない（[掲載しない Experiment の ADR](../../docs/decisions/2026-09-22-unlisted-experiments.md)）。

## Hypothesis

橋の輪郭だけを面で描けば、名前と結び付き、16px でも読める（`LOGO-01`、`LOGO-02`）。
名前の字を倒して橋にすると、比喩と名前が 1 つの形で結び付く。
線の太さを単位にした作図の体系で寸法を揃えると、要素を足さずに整って見える。

| 端点と角  | 半径 2 の丸み              | 利用者の指定（第 3 世代）。桁の端は半円、溝の端も半円        |

### lockup

README のヘッダでは、桁の下端を wordmark の baseline に、図形の高さを cap height に合わせる（`shared/mock.css` の `.db-mark--lockup`）。
図形は viewBox の 8..24（箱の 1/2）にあり、桁の下端は 24（箱の 3/4）なので、箱を cap height（およそ 0.7em）の 2 倍にし、下の余白（箱の 1/4）ぶん下げる。
flex の baseline 合わせは border box の下端を使うので、負の margin ではなく transform で下げる。

### 削除した variant

2026-09-30 に利用者が `d-rings` を採用した。ほかの案はコードを削除し、仮説と軸だけを残す。形は比較ページに残る。

第 1 世代（橋の構造と、面か線か）

- `arch-solid`: 基準。桁とアーチの帯を面で描く。
- `arch-line`: 同じ骨格を線幅 2 で描く。軸は面か線か。
- `beam-solid`: 桁と 2 本の橋脚だけの桁橋。軸は橋の構造。Π に読めた。
- `suspension-solid`: 2 本の塔と主索の吊橋。軸は橋の構造。16px で塊になった。

第 2 世代（倒した D と B）

- `d-over`: 基準。D を反時計回りに倒し、stem を桁、bowl を桁の上のアーチにする。
- `d-over-span`: 桁を bowl より 2 ずつ張り出す。軸は桁の張り出し。
- `d-under`: bowl を桁の下に垂らす。軸は倒す向き。
- `b-over`: B を倒して 2 連のアーチにする。軸は文字。
- `b-over-span`: B の桁を張り出す。軸は文字と桁の張り出し。
- `b-under`: B の bowl を桁の下に垂らす。軸は文字と倒す向き。

第 3 世代（丸み）

- `d-over-round`、`d-over-span-round`、`d-under-round`、`b-over-round`、`b-over-span-round`、`b-under-round`: 第 2 世代の同名の案に半径 2（`span` は 1）の丸みを付ける。軸は丸みの有無。

第 4 世代（作図の体系）

- `d-arc`: 基準。bowl を直線部の無い半円にする。全体 24 × 16、開口 16 × 8。`d-rings` の外形はこれと同じ。
- `b-even`: B の壁、桁、弧の帯をすべて 4 に揃える。4+6+4+6+4 = 24。軸は線の均一化。

## Evaluation

評価を行わずに判断した。
利用者が比較ページと runner の利用画面（タブの 16px、README のヘッダ、avatar、縮小列）で見比べて選んだ。

未評価の軸は次のとおりである。

- 利用者以外による意味の読み取り。橋と D を読めるかは agent の推測にとどまる
- ブラウザの実タブでの 16px の見え方。確かめたのはモックの 16px だけである
- wordmark のフォント。モックの sans は仮で、cap height の 0.7em も仮の値である

## Decision

- 採用: `d-rings`
- 判断者: 利用者
- 判断日: 2026-09-30
- 理由: 利用者は理由を示していない。第 4 世代の依頼は「数式や幾何学模様で、より美しく」で、3 案のうち幾何学模様に最も寄せた案を選んだ。

DocBridge 本体への適用（README のヘッダ、favicon）は未着手である。

## Rejected reasons

2026-09-30 に利用者が `d-rings` を採用したため、第 4 世代のほかの 2 案を却下した。
案ごとの却下理由を利用者は示していない。
次は制作中に agent が観察した懸念であり、却下理由ではない。

| variant  | 制作中の観察（agent）                                          |
| -------- | -------------------------------------------------------------- |
| `d-arc`  | D の読みが弱く、日の出やトンネルにも読める。要素が少なく汎用的 |
| `b-even` | 2 つの開口が 16px で目に寄りやすい。B の読みは強いが橋は弱い   |

第 1〜3 世代は、次の世代へ進む判断で置き換えられた。経緯は Scope と「削除した variant」に記録した。

## Learnings

- 比喩を利用者が先に決めても（橋そのもの）、第 1 世代を見た利用者は名前の文字を組み込む方向へ変えた。ブランドのマークでは、比喩の合意より「名前の字形が比喩を兼ねられるか」を先に試す価値がある。uiux-numa-logo の「名前の文字を核にした形が先に選ばれた」と同じ観察で、2 件目。
- 「丸み」「数式で美しく」のように、利用者の依頼が骨格を保った上での仕上げになってからは、1 世代ごとに変える軸を 1 つに絞れた。仕上げの世代では、体系（単位と半径の規則）を 1 つ決めて全案に当てると、案同士の差が体系の差として説明できる。
- 8 − 2 = 4 + 2 のように、太さの単位を 1 つにすると fillet の円が複数の要素に同時に接する。同心の帯は「単位の倍数の半径」だけで描け、接点の座標も導出で決まる。
- 開口の縦横比が 1:1 に近い 2 つの穴は、16px で目に見える（`b-even` の 6 × 7、keysync-logo の `caps-pair`）。穴は縦長にするか 1 つにする。2 件目の観察であり、原則候補には上げない。
