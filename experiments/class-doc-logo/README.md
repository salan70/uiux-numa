## Problem

授業資料サイト（`class_document`、VitePress で公開）には、サイトを示すマークがない。
ブラウザのタブは既定の favicon で、他のタブと見分けられない。
スライド（Marp）の隅にもサイトを示す印がない。
利用者が渡したテーマに沿って、シンボルマークを描き方の異なる複数案で作り、header、タブ、スライドの隅、単色の縮小で比較する。

採用済みの技術アイコン `line-round` と同じ資料で並ぶため、線幅と端点の扱いをそろえるかどうかも比較の対象にする。

## Target

- 教員（利用者）: 資料サイトとスライドを作る。favicon、header、スライドの隅に同じマークを使いたい。
- 学生: ブラウザのタブを複数開いた状態で 16px の favicon を見分ける。教室で投影されたスライドの隅にマークを見る。

## Scope / Domains

対象領域は logo / brand identity、visual design、iconography、accessibility。
variant で変える軸は次の 2 つにする。

- 比喩と構図: 何をマークにするか。文字（C、D）か、資料の形か、教える行為か
- 描き方: 採用済みの技術アイコンと同じ線画にそろえるか、面で差を付けるか

wordmark（「授業資料」や「class_doc」の文字）は利用画面の HTML テキストで組み、マークと文字の関係は利用画面で見る。

## Constraints

- viewBox は `0 0 32 32`。自己完結した静的 SVG にする。文字（`<text>`）を使わない。`just svg-check --viewbox "0 0 32 32"` を通す。
- 単色（`currentColor`）で成立させる。色はマークの外から与える。
- 16px（favicon）、24px（header）、32px（スライドの隅）、64px（アプリのタイル、反転）で成立する。細部は 16px で判別できる要素だけにする。
- 利用画面のモックは全 variant で同一にし、`diff` で確認する。ブラウザのタブ、サイトの header（wordmark と並ぶ）、スライドの隅、明暗の単色、反転のタイルを並べる。
- 書体とウェイトは `tokens/typography/` を使う。教材固有のサイズと行間は token 化しない。
- 色は VitePress の既定テーマと資料の刷新計画のトークン（primary #002d62、accent #ce1126）から取る。
- 編集用の原本を `variants/<id>/source/mark.svg`、配布用を `variants/<id>/dist/mark.svg` に置く。`index.tsx` は配布用を `?raw` で inline に展開する。
- 部分編集の単位に `part-mark-<role>` の id を付ける。

## Hypothesis

核となる要素 1 つを描き、負の空間で意味を足せば、16px の favicon でも成立する。
無名のサイトでは、扱う対象（授業、資料）を示す descriptive なマークのほうが処理しやすい。
採用済みの技術アイコンと線幅と端点をそろえると資料の中でなじむが、マークとしての識別は弱くなる。
面で描くとタブの中で目立つが、header では技術アイコンと調子が合わなくなる。

### 制作条件

4 案とも、比喩の方向（文字、資料の形、学ぶ行為の道具、抽象記号）を担当者が指定し、Skill `crafting-svg` を読み込んだ subagent に 1 案ずつ任せた。
描き方（線か面か）は各 subagent が選び、理由を残した。
テーマ、viewBox、利用画面のモックは共通。反復は最大 3 回。

### 比喩ごとの記録

### glyph-c

比喩と描き方: ラテン文字 C（class）を角の取れた四角の骨格で組み直した記号。線幅 6 の単線で、面として読ませる。

- 漢字の「授」「学」は骨格だけでも 5 画以上あり 16px で潰れるため却下した（FORM-04、ICON-08）。C と D の合成は、D が閉じた面を要し C は開口で成立するため、1 つの輪郭に両立しないと判断した。
- 端点は `butt`、角はすべて円弧で鋭角なし。腕の先を角の弧の終端で断つことで先端が内を向き、口（8）が内側の面（16）の半分に収まる。
- live area は 2〜30。座標を偶数に置き、16、32、64px で外縁と口がピクセル境界に乗る（SVG-01、ICON-09）。padding 3 は 16px で外縁が半ピクセルに落ちるため不採用にした。
- 負の空間は 16×16 の面と右へ抜ける 6×8 の溝で、資料の一枚と引き出す動きを表す（LOGO-08、LOGO-02）。
- 技術アイコンとは角丸の語彙を共有し、重さは意図的に離した。アイコンは 24px の線画（線幅の比 8.3%）だが、マークは 16px で単独に立つ必要がある（UIFIT-10 からの逸脱として記録）。

| round | 観察                                                                                                                            | 変更                                                                           | 参照                              | 終了理由 |
| ----- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | --------------------------------- | -------- |
| 1     | 円形の C を切り口違いで 4 案試したが、どれも固有の要素がなく汎用の C になった。負の空間に紙を入れる案は外形が閉じて文字が消えた | 骨格を円から角の取れた四角へ。腕の先を弧の終端で断ち内向きに。座標を偶数へ統一 | LOGO-04、LOGO-08、SVG-01、ICON-08 | 指摘あり |
| 2     | live area 24 では内側の面 6px、口 4px と小さく、header で塊に見えた                                                             | live area を 2〜30 に広げ、角の半径を調整。内側の面 16、口 8 に                | FORM-05、LOGO-07、ICON-06         | 指摘あり |
| 3     | 線幅 4 では 16px で「角丸四角の枠」に見え、文字が読めない                                                                       | 線幅 6 を確定                                                                  | SVG-02、LOGO-01                   | 指摘なし |

未解決: 負の空間が「資料の一枚」と読めるかは未検証。24px は偶数格子に乗らない（0.75 倍で半ピクセル）。他サイトの C 系 favicon との識別は未検証。

### stacked-sheets

比喩と描き方: 重なった 2 枚の紙を面で描き、負の空間の隙間で分ける。

- 前の 1 枚を面で置き、後ろの 1 枚を (+6, -6) ずらして帯だけを見せる。右上への斜めのずれで「増える」を示す（LOGO-02、LOGO-08）。
- 綴じられたページの案は、綴じ穴と綴じ代が 16px で読めないため却下した（FORM-04、ICON-08）。
- 2 枚の分離は線ではなく負の空間の隙間 2（16px で 1px）だけで作る。
- 角丸は前の紙 2、削り取る形はその +2 で 4。技術アイコンとは丸い語彙だけを共有する。
- 全座標を偶数に置き、16px で輪郭と隙間をピクセル境界に乗せた（SVG-01、ICON-09）。
- 技術アイコンとはあえて差を付けた。線画の中でマークだけが面になり、タブと header で先に読める。

| round | 観察                                                                 | 変更                                            | 参照                      | 終了理由 |
| ----- | -------------------------------------------------------------------- | ----------------------------------------------- | ------------------------- | -------- |
| 1     | 3 枚版は 16px で縞の塊になり、2 枚版は分離が読めた                   | 3 枚を却下し 2 枚に                             | FORM-04、ICON-08、ICON-11 | 指摘なし |
| 2     | 奇数座標だと 16px で全辺が半ピクセルに乗り、輪郭と隙間が灰色ににじむ | 全座標を偶数に置き直し、帯 4、隙間 2、角丸 2 に | SVG-01、ICON-09           | 指摘なし |
| 3     | 利用画面でタブ 16px と header 24px のマークが小さい                  | 前の紙を 18×22、全体を 24×28 に拡大             | FORM-05、LOGO-07          | 上限到達 |

未解決: 面 2 枚の斜めのずれは copy や duplicate ボタンの図像に近い。固有性は縦長の比、右辺の途中で終わる帯、隙間と帯の比 1:2 だけで、`LOGO-04` の「固有の要素 1 つ」としては弱い。実サイトの favicon（ブラウザ生成の縮小）と Marp の PDF 書き出しは未確認。

### open-book

比喩と描き方: 開いた本を正面から面で描き、背へ細る楔の負の空間で分ける。

- 書見台は 64px でシーソーに見え、黒板は 16px で角丸長方形になり技術アイコンの `terminal` と衝突するため却下した（ICON-03、FORM-04）。
- 線幅 3 の線画案は 16px でページ内部の空洞が濁り、シルエットが弱くなったため面にした（LOGO-01、LOGO-07）。
- 外側の上角は尖らせてページの角にし、下角だけ角丸 2 にして綴じ側を示す。
- 左ページの上辺を約 24 度に寝かせ、右ページを約 48 度に立てる非対称（LOGO-03）と、上端幅 6 から先端で 0 になる楔（LOGO-08、FORM-10）で固有性を作った。中央の縦線は引かない。
- `stacked-sheets` と面という技法は重なるが、比喩、負の空間の作り方、角の扱いで分けた。

| round | 観察                                                                                                     | 変更                                                                     | 参照                      | 終了理由 |
| ----- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------- | -------- |
| 1     | 方向 4 案を比較した。書見台はシーソー、線の本は 16px で内部が濁る、対称の谷は既製の `book-open` そのもの | 非対称の見開きを採用                                                     | ICON-03、FORM-04、LOGO-04 | 指摘なし |
| 2     | 谷が上下に貫通すると 2 つのブロックに割れて「本」に見えない（16px）                                      | 内側の辺を傾け、背へ細る楔にして下端で閉じた                             | LOGO-08、FORM-10          | 指摘なし |
| 3     | 16px のタブの塊がグレーの丸より軽い。左ページの傾きが右と近く W に見える                                 | 下辺を下げて live area を 24×24 にし、左ページの上辺を寝かせて差を広げた | FORM-05、FORM-09、LOGO-03 | 指摘なし |

未解決: 16px で「本」と読めるかは自己確認にとどまり、W やチェックマークに見える可能性が残る。`stacked-sheets` と面という技法が重なるため、並べたときの区別は比喩と角の扱いに依存する。lockup の clear space と最小サイズ（LOGO-06）、PWA の safe zone（LOGO-09）は Brief の範囲外で未定義。

### chalk-mark

比喩と描き方: 印と進みの抽象記号。チェック 1 本を左下から右上へ太る筆致として面で描き、垂直の切れ目で 2 つに割る。

- 階段（直交の段）は 64px で意味が消え、丸は 16px で汎用のリングになったため却下した。
- 切れ目が作る「小さい印 → 大きく伸びる」で、回を追って進むことを負の空間に読ませる（LOGO-08、FORM-10）。
- 直線と平らな切り口だけで作り、曲線と角丸を使わない。先端の切り口は腕にほぼ直交させ、勢いの向きを残す。
- 幅は短い腕 3.8、長い腕の根元 4.8、先端 7.8 の約 1.6 倍のテーパーを付けた。
- 技術アイコンとはあえて差を付けた。面なので、資料本文でアイコン列と並んだときにサイトの印だけが手前に出る。

| round | 観察                                                                | 変更                                       | 参照             | 終了理由 |
| ----- | ------------------------------------------------------------------- | ------------------------------------------ | ---------------- | -------- |
| 1     | 16px で短い腕が細く、右上の塊と釣り合わない                         | 短い腕の幅を 2.7 から 3.8 へ               | FORM-09、FORM-03 | 指摘あり |
| 2     | 利用画面のタブ 16px と header 24px で、左の破片が独立した点に見える | 切れ目を幅 4 から 3 へ寄せ、質量を増やした | ICON-08、FORM-10 | 指摘あり |
| 3     | 16/24/32/64px、明暗、利用画面で課題ありが残らない                   | なし                                       | なし             | 指摘なし |

未解決: 抽象記号なので「授業資料」を想起させず、`LOGO-02`（無名では descriptive が有利）に正面から反する。補いとして lockup を基本形にし、チェックを採点と理解の確認という授業の行為に結び付け、切れ目で回を示したが、いずれも仮説で未検証である。他サイトの汎用チェック favicon と区別できるかも未検証。16px では切れ目の面が半ピクセルに乗る。ICO 変換後の実ブラウザでの見え方は未確認。

## Evaluation

多観点の評価は行っていない。
判断は、4 案の比較シート（16/24/32/64px、明暗）と利用画面の確認による。
評価を経ない判断の扱いは[補足の ADR](../../docs/decisions/2026-09-17-named-variants-and-unevaluated-decisions.md)に従う。

## Decision

4 案とも採用しない。この Experiment は判断をもって終了する。

- 判断者: リポジトリの所有者
- 判断日: 2026-09-19
- 根拠: 4 案の比較シートと利用画面の確認

未評価の軸は次のとおり。
consistency、accessibility、discoverability、visual hierarchy、brand fit、maintainability のいずれも、多観点の評価を経ていない。
16px で成立することと `just svg-check` を通ることは、制作時の自己確認で確かめている。

## Rejected reasons

4 案（`glyph-c`、`stacked-sheets`、`open-book`、`chalk-mark`）を採用しなかった理由は次のとおり。

- 比喩が合わない: 文字（C）、資料の形、学ぶ行為の道具、抽象記号のいずれも、このサイトを表すものとして合わなかった。
- 調子が合わない: 学生が読む資料の印象として、方向が合わなかった。
- 完成度が低い: 形の細部とバランスが粗い。

判断者と判断日は Decision と同じである。

## Learnings

- テーマを利用者が渡し、描き方や比喩の方向を AI が決める進め方は、機能アイコン（`class-tech-icons`）では成立したが、ロゴでは成立しなかった。アイコンは意味が機能で決まるのに対し、ロゴは比喩と調子そのものが判断の対象になる。ブランドを表す成果物では、比喩と目指す印象を先に利用者と決める必要がある。
- 3 回の自己確認による反復では、ロゴに求められる完成度に届かなかった。機能アイコンでは十分だった反復の回数と確認の項目が、ロゴでは足りない。
- 4 案とも 16px で成立し、`just svg-check` を通り、利用画面で破綻しなかった。機械検査と自己確認が通ることと、採用に値することは別である。この Experiment はその差を示した。
- 却下した 4 案は学習材料として残す。比喩の方向（文字、資料の形、道具、抽象記号）を変えても採用に至らなかったという記録は、次にロゴを作るときの出発点になる。
